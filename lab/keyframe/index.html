キーフレーム（クリップの中で、値を時間とともに動かす）

拡大・位置・不透明度を、クリップの中で打点（キーフレーム）で動かします。 この画面の本題は「編集しても打点が期待どおりに付いてくるか」で、 曲線の引き方そのものはどの持ち方でも同じです（測った表は lab/keyframe/README.md）。処理はすべてこのページの中で完結し、どこにも送信しません。

1. 素材とクリップ

並んでいるのは lab:keyframe:probe が測っているのと同じ素材 6 本です。 打点も、そこに書いてある曲線をそのまま入れてあります （画面だけ別の素材で触ると、出た数字を表と突き合わせられなくなるため）。

2. 打点をつまむ

横はタイムラインの秒、縦は値です。何も無い所を押すと打点が増え、 打点を掴むと動きます（Alt を押しながら、または右クリックで消えます）。 横軸をタイムラインの秒にしてあるのが、この画面でいちばん効いた所—— 打点の秒は時間軸ごとに意味が違うので、そのまま並べると 3 通りを見比べられません。 代わりに、打点の秒 → タイムラインの秒の逆向きの写しが要りました （timeAtKeyTime()。読むだけなら片道で足ります）。

曲線（打点から読んだ値）　打点 　クリップの外に居る打点　クリップの範囲 　いま見ている時刻
クリップの外の打点も消しません——頭を詰めて戻したときに戻らなくなるためです（9/27 に測った）

3. 出ている絵（本体へ差す形）

本体の renderer.ts は clip.opacity のような素の数を そのまま使っています。ここは同じ式（compose.ts＝fitRect() と fadeEnvelope() の写し）に sampleClipValue() を差した形で、 差し方が合っているかは値だけ見ても分かりません （値が正しくても、差す場所を間違えれば絵だけが違う）。

0.00s

4. 編集して、打点が付いてくるか見る

本体の操作（src/model/ops.ts の写し）を当てます。打点の付け替えは 1 行も書いていません——それで期待どおりになるのが 9/27 の結論で、ここはその確かめです。 ずれは lab:keyframe:probe と同じ物差し（1 コマずつ、期待との差の最大）で、 この素材が期待している形（）に対して測っています。

まだ何も当てていません。

3 通りを並べて出しているのは、既定が「勝っている」ことを目で見るため。 いま選んでいる時間軸だけを出すと、0 が「正しい」のか「そもそもずれない素材」なのかが読めません。

5. セルフテスト

合成した値で計算そのものを確かめます。素材が無くても、壊れていないことがここで分かります。 コマンドライン（npm run lab:test）が見ているものと同じです。
