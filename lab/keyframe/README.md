# keyframe — 時間で変化する値の持ち方

拡大・位置・不透明度・音量を、クリップの中で時間とともに動かす。
本体（`src/model/types.ts`）はいまこれらを**素の数**で持っているので、
入れるならモデルに手が入る。**そこで先に、値の持ち方だけをここで試した。**

```
npm run lab:keyframe         # 読み出しの費用と、保存の太り
npm run lab:keyframe:probe   # 持ち方 4 通りを編集の操作に当てて測る
npm run lab:test             # 検算（41 件。ほかの試作と続けて走る）
```

## 中身

| ファイル | 役目 |
| --- | --- |
| `src/value.ts` | 打点の並べ方と、1 コマぶんの取り出し（**秒しか見ない**。クリップを知らない） |
| `src/track.ts` | **本体へ持っていく形**。クリップの上で読む / 打点を置く / 消す |
| `src/timebase.ts` | 測るための 4 つの時間軸と、本体から写した編集の操作 |
| `src/scenarios.ts` | 素材 6 本と**正解**（期待の形 3 通り） |

`value.ts` と `track.ts` を分けてあるのは、**並べ方の議論と「何秒として読むか」の議論が別物**で、
混ぜると壊れたときにどちらの話か読めなくなるため。

## 何を決めたか

**打点の時刻を「何の秒」で持つかは、値ごとに選ぶ。** 3 通りあり、既定は種類で決まる。

| 時間軸 | 打点の 2.0 秒が指すもの | 使う値 |
| --- | --- | --- |
| `source` | 素材の 2.0 秒 | 映像・音（既定） |
| `local` | クリップの頭から 2.0 秒 | テロップ・静止画（既定） |
| `fraction` | 尺の 2.0 割（0〜1 で書く） | ケンバーンズのような「尺いっぱいに動かす」型が名乗る |

持ち方は `number | { base?, keys: [{ t, v, ease? }] }`。**素の数をそのまま受ける**ので、
保存済みのプロジェクトも履歴もそのまま読め、動かしていないクリップは JSON が 1 文字も増えない。

## なぜそうしたか（測ってから決めた）

### 1. 時間軸と「期待の形」は 1 対 1 だった

素材 6 本 × 編集 6 操作（掴んで動かす / 頭を詰める / 尻を詰める / 割る / 速さを変える / リップルで詰まる）で、
**編集したあとの値が期待どおりか**を 1 コマずつ測った（正解の作り方は `src/scenarios.ts` の頭に書いてある）。
打点の付け替えを**一切しない**場合:

| 期待 | `source` | `local` | `absolute` | `fraction` |
| --- | --- | --- | --- | --- |
| `content`（絵に付く・4 本） | **24/24** | 13/24 | 13/24 | 9/24 |
| `head`（クリップの頭に付く・1 本） | 5/6 | **6/6** | 2/6 | 3/6 |
| `stretch`（尺に伸び縮み・1 本） | 3/6 | 3/6 | 2/6 | **6/6** |

**3 つとも、自分の期待をちょうど満たし、他の期待は満たさない。**
`absolute`（タイムラインの秒）はどの期待でも勝たないので捨てた。

### 2. 「1 つに決めて、付け替えで救う」は筋が悪い

時間軸を 1 つに決めて、編集のたびに打点を付け替える形も測った（表の 2 段目）。
**絵に付ける付け替えを書けば、4 通りとも `content` は 24/24 になる。**
ただしそれは**「絵に付く」を全部の値に押し付ける**ことなので、
テロップの出（`head`）とケンバーンズ（`stretch`）が道連れで落ちる（4/6・3/6）。

> **付け替えの中身そのものが「どの期待を選ぶか」の宣言になっている。**
> 最初は付け替えを書いた表しか作っておらず、テロップとケンバーンズが 4 通りとも同じ所で落ちた。
> 落ちていたのは時間軸ではなく、こちらが書いた付け替えだった。

さらに、付け替えは**本体の操作に手を入れる箇所**として残る:

| 時間軸 | 付け替えが要る操作 |
| --- | --- |
| `source` | **0 箇所** |
| `local` | 3 箇所（頭を詰める・割る・速さ） |
| `absolute` | 3 箇所（動かす・速さ・リップル） |
| `fraction` | 4 箇所（頭・尻・割る・速さ） |

**上の表（付け替えなし）で 3 つが成り立つので、この列は全部 0 箇所で済む。**
`src/model/ops.ts` は `structuredClone` でクリップを丸ごと写すので、
**編集の操作には 1 行も足さずに打点が付いてくる。**

### 3. 打点は刈らない

「見えない所（詰めて隠れた頭の側）の打点は消してよいのでは」を測った。
頭を 1 回詰めて、同じだけ戻す往復で:

| | 打点を残す | 見えない打点を刈る |
| --- | --- | --- |
| 4 通りとも | **0** | **1.0000** |

`trimLeft` は本体でも可逆な操作（素材の頭までは戻せる）なので、
**刈ると「戻したのに絵が戻らない」になる。**

> **最初は `source` だけ刈っても 0 のままだった。素材の都合だった。**
> 置いていた 5 本はどれも打点がクリップの頭より後ろにあり、刈っても何も起きなかった。
> 頭の側に打点を持つ素材（`video-fade-in`）を足したら、4 通りとも 1.0000 になった。

### 4. 繋ぎ方（ease）は打点に持たせる

`hold` / `linear` / `easeIn` / `easeOut` / `easeInOut` の 5 つ。
**区間ではなく手前の打点に持たせた**のは、打点を消したときにどの繋ぎ方が残るかが一意に決まるため。
`easeOut` は本体のテロップと同じ式（`1-(1-u)^3`、`src/engine/renderer.ts` の `textAnimation()`）。

## 費用（`npm run lab:keyframe`）

**設定を交互に回して中央値**を取る（`export-cost` が 2026-09-26 に確定させた測り方）。

| 持ち方 | 1 回あたり | 書き出し 1 本ぶん（60 秒・30fps・3 本重なり・1 本に 4 値＝21,600 回） |
| --- | --- | --- |
| 素の数（いまの本体） | 2.1 ns | 0.04 ms |
| 打点 2 個 | 41 ns | 0.87 ms |
| 打点 64 個 | 54 ns | 1.16 ms |
| 打点 512 個 | 73 ns | 1.57 ms |

（交互に回した中央値でも**回ごとに 1 割ほど振れる**ので、読むのは桁だけにしてある）

素の数に比べれば 20 倍だが、**書き出し 1 本で 1ms 前後**。
同じ書き出しの 1 コマぶんのデコードが 2.3〜6.5ms（`export-cost` の実測）なので、**桁で届かない。**

保存の太りは、打点 1 個 **17 バイト**（繋ぎ方まで書くと 36）。
30 本のプロジェクトの 3 本に 6 個ずつ置いて **+5.7%**。

### 探し方は二分探索（速いほうではない）

| 打点 | 二分 | 線形 |
| --- | --- | --- |
| 2 | 40.3 ns | **33.2 ns** |
| 16 | 44.4 ns | **37.8 ns** |
| 32 | **46.5 ns** | 50.6 ns |
| 512 | **73.2 ns** | 282.7 ns |

**ふつうに使う 2〜16 個では線形のほうが速い**（2 割）。それでも二分にしたのは、
**音量の曲線のように打点が数百になりうる値があり、そこで 3.9 倍に開く**ため。
2 割が惜しい側の絶対値は 1 ミリ秒の 2 割なので、悪くなる側の桁を取った。

> 最初は線形が 5 倍速いという数字が出た。**比べる相手が繋ぎ方の計算を通っていなかった**
> （探し方の差ではなく `easeAt()` の呼び出しを測っていた）。

## 本体に入れるときの接続先

- 読む所: `src/engine/renderer.ts` の `drawVisualClip()` / `drawTextClip()`、`src/engine/offline-export.ts`。
  `clip.opacity` を `sampleClipValue(clip, clip.opacity, time, 1)` に替える。
  素の数のままのクリップは 1 コマも変わらない。
- 型: `src/model/types.ts` の `opacity` / `scale` / `x` / `y` / `rotate` / `volume` /
  `Effect.intensity` を `AnimatedTrack` にする。読み書きしている所は型で全部出る。
- **フェードとテロップの出は別物として残す。** 本体は `opacity` に `fadeEnvelope()` と
  テロップの `animation` を掛けているので、打点はそれと**掛け算で重なる**。
  片方を打点で置き換えるかは別の判断。
- 書く所（画面）はまだ無い。`putKeyAtTime()` / `removeKeyAt()` までは置いてある。

## まだ無いもの

- **画面（デモ）。** 打点を置く・つまむ・繋ぎ方を選ぶ所。ほかの試作と同じで、
  計算と測る段が先、画面は次の回。
- **本物のクリップを 2 本重ねた状態での実測。** いまの費用は合成した呼び出し回数の掛け算。
- 値が 2 つ以上そろって動くもの（位置の X と Y を 1 つの打点で持つか）。いまは値ごとに独立。
