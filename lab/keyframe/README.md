# keyframe — 時間で変化する値の持ち方

拡大・位置・不透明度・音量を、クリップの中で時間とともに動かす。
本体（`src/model/types.ts`）はいまこれらを**素の数**で持っているので、
入れるならモデルに手が入る。**そこで先に、値の持ち方だけをここで試した。**

```
npm run lab:keyframe:demo    # 画面を開く（打点を置く・つまむ・繋ぎ方を選ぶ）
npm run lab:keyframe         # 読み出しの費用と、保存の太り
npm run lab:keyframe:probe   # 時間軸 4 通りを編集の操作に当てて測る
npm run lab:keyframe:hold    # **既定でない時間軸をどこに持つか**を 4 通り測る
npm run lab:keyframe:uitest  # 画面まで通して確かめる（playwright が無ければ飛ばす）
npm run lab:test             # 検算（65 件。ほかの試作と続けて走る）
```

## 中身

| ファイル | 役目 |
| --- | --- |
| `src/value.ts` | 打点の並べ方と、1 コマぶんの取り出し（**秒しか見ない**。クリップを知らない） |
| `src/track.ts` | **本体へ持っていく形**。クリップの上で読む / 打点を置く / 消す |
| `src/timebase.ts` | 測るための 4 つの時間軸と、本体から写した編集の操作 |
| `src/hold.ts` | **既定でない時間軸をどこに持つか**を 4 通り並べる所（測るための足場と、外した軸が要る素材 4 本） |
| `src/scenarios.ts` | 素材 6 本と**正解**（期待の形 3 通り）、ずれを測る物差し |
| `src/compose.ts` | **絵にする所**（本体の `fitRect()` / `fadeEnvelope()` の写し）。DOM は要らない |
| `src/demo.ts` ・ `index.html` | 画面。判断はしない（上の 5 つを呼ぶだけ） |

`value.ts` と `track.ts` を分けてあるのは、**並べ方の議論と「何秒として読むか」の議論が別物**で、
混ぜると壊れたときにどちらの話か読めなくなるため。

## 何を決めたか

**打点の時刻を「何の秒」で持つかは、値ごとに選ぶ。** 3 通りあり、既定は種類で決まる。

| 時間軸 | 打点の 2.0 秒が指すもの | 使う値 |
| --- | --- | --- |
| `source` | 素材の 2.0 秒 | 映像・音（既定） |
| `local` | クリップの頭から 2.0 秒 | テロップ・静止画（既定） |
| `fraction` | 尺の 2.0 割（0〜1 で書く） | ケンバーンズのような「尺いっぱいに動かす」型が名乗る |

持ち方は `number | { base?, keys: [{ t, v, ease? }] } | { base, v }`。**素の数をそのまま受ける**ので、
保存済みのプロジェクトも履歴もそのまま読め、動かしていないクリップは JSON が 1 文字も増えない。
3 つ目（`{ base, v }`）は**打点を持たないが時間軸だけ覚えている形**で、
「打点を全部消したら軸ごと消える」を塞ぐために 2026-09-27 の 3 回目に足した（下の節）。

## なぜそうしたか（測ってから決めた）

### 1. 時間軸と「期待の形」は 1 対 1 だった

素材 6 本 × 編集 6 操作（掴んで動かす / 頭を詰める / 尻を詰める / 割る / 速さを変える / リップルで詰まる）で、
**編集したあとの値が期待どおりか**を 1 コマずつ測った（正解の作り方は `src/scenarios.ts` の頭に書いてある）。
打点の付け替えを**一切しない**場合:

| 期待 | `source` | `local` | `absolute` | `fraction` |
| --- | --- | --- | --- | --- |
| `content`（絵に付く・4 本） | **24/24** | 13/24 | 13/24 | 9/24 |
| `head`（クリップの頭に付く・1 本） | 5/6 | **6/6** | 2/6 | 3/6 |
| `stretch`（尺に伸び縮み・1 本） | 3/6 | 3/6 | 2/6 | **6/6** |

**3 つとも、自分の期待をちょうど満たし、他の期待は満たさない。**
`absolute`（タイムラインの秒）はどの期待でも勝たないので捨てた。

### 2. 「1 つに決めて、付け替えで救う」は筋が悪い

時間軸を 1 つに決めて、編集のたびに打点を付け替える形も測った（表の 2 段目）。
**絵に付ける付け替えを書けば、4 通りとも `content` は 24/24 になる。**
ただしそれは**「絵に付く」を全部の値に押し付ける**ことなので、
テロップの出（`head`）とケンバーンズ（`stretch`）が道連れで落ちる（4/6・3/6）。

> **付け替えの中身そのものが「どの期待を選ぶか」の宣言になっている。**
> 最初は付け替えを書いた表しか作っておらず、テロップとケンバーンズが 4 通りとも同じ所で落ちた。
> 落ちていたのは時間軸ではなく、こちらが書いた付け替えだった。

さらに、付け替えは**本体の操作に手を入れる箇所**として残る:

| 時間軸 | 付け替えが要る操作 |
| --- | --- |
| `source` | **0 箇所** |
| `local` | 3 箇所（頭を詰める・割る・速さ） |
| `absolute` | 3 箇所（動かす・速さ・リップル） |
| `fraction` | 4 箇所（頭・尻・割る・速さ） |

**上の表（付け替えなし）で 3 つが成り立つので、この列は全部 0 箇所で済む。**
`src/model/ops.ts` は `structuredClone` でクリップを丸ごと写すので、
**編集の操作には 1 行も足さずに打点が付いてくる。**

### 3. 打点は刈らない

「見えない所（詰めて隠れた頭の側）の打点は消してよいのでは」を測った。
頭を 1 回詰めて、同じだけ戻す往復で:

| | 打点を残す | 見えない打点を刈る |
| --- | --- | --- |
| 4 通りとも | **0** | **1.0000** |

`trimLeft` は本体でも可逆な操作（素材の頭までは戻せる）なので、
**刈ると「戻したのに絵が戻らない」になる。**

> **最初は `source` だけ刈っても 0 のままだった。素材の都合だった。**
> 置いていた 5 本はどれも打点がクリップの頭より後ろにあり、刈っても何も起きなかった。
> 頭の側に打点を持つ素材（`video-fade-in`）を足したら、4 通りとも 1.0000 になった。

### 4. 繋ぎ方（ease）は打点に持たせる

`hold` / `linear` / `easeIn` / `easeOut` / `easeInOut` の 5 つ。
**区間ではなく手前の打点に持たせた**のは、打点を消したときにどの繋ぎ方が残るかが一意に決まるため。
`easeOut` は本体のテロップと同じ式（`1-(1-u)^3`、`src/engine/renderer.ts` の `textAnimation()`）。

## 費用（`npm run lab:keyframe`）

**設定を交互に回して中央値**を取る（`export-cost` が 2026-09-26 に確定させた測り方）。

| 持ち方 | 1 回あたり | 書き出し 1 本ぶん（60 秒・30fps・3 本重なり・1 本に 4 値＝21,600 回） |
| --- | --- | --- |
| 素の数（いまの本体） | 2.6 ns | 0.06 ms |
| 畳んだ形 `{ base, v }` | 5.2 ns | 0.11 ms |
| 打点 2 個 | 42 ns | 0.91 ms |
| 打点 64 個 | 57 ns | 1.23 ms |
| 打点 512 個 | 80 ns | 1.72 ms |

（交互に回した中央値でも**回ごとに 1 割ほど振れる**ので、読むのは桁だけにしてある）

素の数に比べれば 20 倍だが、**書き出し 1 本で 1ms 前後**。
同じ書き出しの 1 コマぶんのデコードが 2.3〜6.5ms（`export-cost` の実測）なので、**桁で届かない。**

保存の太りは、打点 1 個 **17 バイト**（繋ぎ方まで書くと 36）。
30 本のプロジェクトの 3 本に 6 個ずつ置いて **+5.7%**。

### 探し方は二分探索（速いほうではない）

| 打点 | 二分 | 線形 |
| --- | --- | --- |
| 2 | 40.3 ns | **33.2 ns** |
| 16 | 44.4 ns | **37.8 ns** |
| 32 | **46.5 ns** | 50.6 ns |
| 512 | **73.2 ns** | 282.7 ns |

**ふつうに使う 2〜16 個では線形のほうが速い**（2 割）。それでも二分にしたのは、
**音量の曲線のように打点が数百になりうる値があり、そこで 3.9 倍に開く**ため。
2 割が惜しい側の絶対値は 1 ミリ秒の 2 割なので、悪くなる側の桁を取った。

> 最初は線形が 5 倍速いという数字が出た。**比べる相手が繋ぎ方の計算を通っていなかった**
> （探し方の差ではなく `easeAt()` の呼び出しを測っていた）。

## 本体に入れるときの接続先

- 読む所: `src/engine/renderer.ts` の `drawVisualClip()` / `drawTextClip()`、`src/engine/offline-export.ts`。
  `clip.opacity` を `sampleClipValue(clip, clip.opacity, time, 1)` に替える。
  素の数のままのクリップは 1 コマも変わらない。
- 型: `src/model/types.ts` の `opacity` / `scale` / `x` / `y` / `rotate` / `volume` /
  `Effect.intensity` を `AnimatedTrack` にする。読み書きしている所は型で全部出る。
- **フェードとテロップの出は別物として残す。** 本体は `opacity` に `fadeEnvelope()` と
  テロップの `animation` を掛けているので、打点はそれと**掛け算で重なる**。
  片方を打点で置き換えるかは別の判断。
- 書く所（画面）はまだ無い。`putKeyAtTime()` / `removeKeyAt()` までは置いてある。

## 画面（2026-09-27 の 2 回目）

`npm run lab:keyframe:demo`。素材は `probe.mjs` と**同じ 6 本**で、打点も同じ曲線が入っている
（画面だけ別の素材で触ると、出た数字を上の表と突き合わせられなくなる）。
確かめは `npm run lab:keyframe:uitest`（75 件。`lab:uitest` からも走る）。

**画面を作って要ったものが 3 つある。どれも「読む」側には出てこない。**

| 要ったもの | なぜ読む側には出てこないか | 測った被害 |
| --- | --- | --- |
| `timeAtKeyTime()`（逆向きの写し） | 読むのは「タイムラインの秒 → 打点の秒」の片道。**描く / つまむには逆が要る** | 無いと打点を置く場所が決まらない |
| `keyTimeInUnclamped()`（丸めない前向き） | 本体の `sourceTimeAt()` はクリップの頭で丸める。読む側は外を読まない | 丸めた式で外の打点を掴むと **0.517 秒**飛ぶ（頭に張り付く） |
| `putKeyAtTime(..., base)` | 時間軸は値と一緒に持っているので、**打点が 0 個の値には残っていない** | 既定へ戻ると打点の立つ所が **4.00 秒**動く（尺 5 秒の静止画） |

> 3 つ目は **2026-09-27 の 3 回目に要らなくなった**（畳んだ形が軸を持つようになった）。
> 引数は素の数に最初の打点を置く道のために残してある。下の「既定でない時間軸をどこに持つか」を参照。

### つまんでいる間は軸を止める

軸（見せる秒と値の範囲）を打点の位置から決めていると、**つまんでいる間に軸が伸びて、
指の下で目盛りが動く。**

| つまむ向き | 軸を合わせ直す | 掴んだ瞬間の軸で止める |
| --- | --- | --- |
| 値の上へ 30 画素（狙い +0.0707） | **+0.640（0.569 余計＝狙いの 8.0 倍ぶん）** | +0.0707（ずれ 1.9e-9） |
| 横へ 200 画素・クリップの外へ（狙い +1.655s） | **+2.79s（1.13s 余計）** | +1.655s（ずれ 1.7e-7s） |

**伸びる向きへ引っ張ったときだけ出る**（範囲の内側で動かしているあいだは 1 桁も違わない）。
なので「動かしてみたら合っている」では気づけない。

### 1 画素が指す打点の秒は、時間軸と速さで変わる

| | source（速さ ×1） | source（速さ ×2） | local | fraction |
| --- | --- | --- | --- | --- |
| 1 画素 | 8.3ms | **13.8ms** | 5.5ms | 0.14% |

同じ画面幅でも、**素材の秒で持つ値は速さの分だけ粗くなる**（2 倍速なら 1 画素で 2 コマ分動く）。
つまむ側の分解能は時間軸の選び方で決まるので、**目盛りを秒で書くなら時間軸ごとに変える**必要がある。
（`reframe` が 2026-09-25 に踏んだ「つまみの目盛りが既定を表せないと画面だけ黙ってずれる」と同じ形の話。）

### 絵は、値が合っていても確かめたことにならない

`compose.ts` に本体の `fitRect()` / `fadeEnvelope()` を写して、**画面と Node の両方から同じ関数を呼ぶ**。
`uitest` は画面に出ている矩形と透明度を Node 側の計算と突き合わせる（7 コマで差 0）。
値だけ見ていると、**差す場所を間違えても数字は正しいまま**で絵だけが違う
（表紙の画面が 2026-09-23 に踏んだ「すり替わっても分布が変わらない」と同じ）。
プレビューの検査は**わざと出ない側も見る**（打点で不透明度 0 の所は明るさ 0.0、1 の所は 136.5）。

打点とフェードは**掛け算で重なる**ところまで画面から触れる（打点 0.4 × フェード 0.5 = 0.20）。
どちらかを打点で置き換えるかは、まだ決めていない。

## 既定でない時間軸をどこに持つか（2026-09-27 の 3 回目）

`npm run lab:keyframe:hold`。**打点が 0 個になると時間軸が消える**——1 回目に決めた
「軸は値と一緒に持つ」の穴で、2 回目に画面を作って出た。画面は自分の欄に覚えて逃げていたが、
**覚えているのが画面なら保存も複製もコピーも運べない。**

### 測るのに要った素材 4 本

`SCENARIOS` の 6 本のうち、既定から外した軸が要るのは `image-kenburns` だけだった。
1 本では「その素材の都合」と見分けが付かないので、**種類の違う 3 本を足した**（`src/hold.ts`）。

| 素材 | 種類 | 既定 | 選ぶ軸 | 期待 |
| --- | --- | --- | --- | --- |
| `image-kenburns` | image | local | `fraction` | stretch |
| `video-slow-push` | video | source | `fraction` | stretch |
| `video-open` | video | source | `local` | head |
| `text-scroll` | text | local | `fraction` | stretch |

4 本とも、**選んだ軸なら編集 6 操作を素で通る**（測定の 0 段目。ここが崩れていると
「軸が消えた被害」と「軸の選び間違い」が混ざる）。

### 分かれるのは 2 つの操作だけ

| 操作 | `inKeys`（いまの形） | `emptyKeys` | `stillValue` | `onClip` |
| --- | --- | --- | --- | --- |
| 保存して読み直す | 軸 ○ 値 ○ | ○ ○ | ○ ○ | ○ ○ |
| クリップを複製する | ○ ○ | ○ ○ | ○ ○ | ○ ○ |
| クリップを割る | ○ ○ | ○ ○ | ○ ○ | ○ ○ |
| **打点を全部消す** | **軸 ✗** 値 ○ | 軸 ○ **値 ✗** | ○ ○ | ○ ○ |
| **打点を置く前に軸を選ぶ** | **軸 ✗**（書く場所が無い） | 軸 ○ **値 ✗** | ○ ○ | ○ ○ |
| **値だけ別のクリップへ写す** | ○ ○ | ○ ○ | ○ ○ | **軸 ✗** 値 ○ |

- `inKeys` = 打点の列と一緒（いまの形）／`emptyKeys` = 空の列を残す（`{ base, keys: [] }`）／
  `stillValue` = 畳んだ形が軸と値を両方持つ（`{ base, v }`）／`onClip` = クリップ側に値の名前ごとの表。
- **上の 3 つはクリップごと運ぶ操作なので 4 通りとも通る。** `src/model/ops.ts` が
  `structuredClone` でクリップを丸ごと写すからで、**軸を値に置いてもクリップに置いても同じ。**
- 分かれるのは**値と軸が別々に動く瞬間**だけ。クリップの形は 1 つも変わらないので、
  9/27 の 1 回目・2 回目の測定（編集の操作の表）には**原理的に出てこない列**だった。

### 「空の列を残さない」の理由は、軸ではなく値だった

`track.ts` には「空の列（`{ base, keys: [] }`）は残さない」と書いてあり、理由は
**読む側が毎コマ `fallback` を通るから**だった。実際に測ると `emptyKeys` は軸を保つが値を落とす
（畳んだ 1.2 が既定の 1.0 として読まれる）。**逆に素の数へ畳むと値は残るが軸が落ちる。**
`{ base, v }` は**両方置くだけ**で、どちらも立つ。

### 軸が落ちたあとの被害

打点を全部消して**タイムラインの同じ所に置き直し**、そのあと編集したときの当たり:

| 素材 | 期待 | `inKeys` | `emptyKeys` | `stillValue` | `onClip` |
| --- | --- | --- | --- | --- | --- |
| `image-kenburns` | stretch | 3/6（最悪 0.100） | 6/6 | 6/6 | 6/6 |
| `video-slow-push` | stretch | 2/6（0.109） | 6/6 | 6/6 | 6/6 |
| `video-open` | head | 3/6（1.000） | 6/6 | 6/6 | 6/6 |
| `text-scroll` | stretch | 3/6（0.500） | 6/6 | 6/6 | 6/6 |
| 合計 | | **11/24** | 24/24 | 24/24 | 24/24 |

**置き直した直後はどの持ち方でも 1 コマも違わない**（タイムラインの同じ所に置くので）。
差が出るのはそのあと編集したときなので、**「置き直して動かしてみたら合っている」では気づけない。**

軸が落ちると、打点の立つ所そのものも動く（写し先のクリップ＝頭 +3 秒・尺 1.5 倍で測った最大）:

| 素材 | 選ぶ軸 → 落ちる先 | 打点のずれ |
| --- | --- | --- |
| `image-kenburns` | fraction → local | 6.50 秒 |
| `video-slow-push` | fraction → source | 15.00 秒 |
| `video-open` | local → source | 10.00 秒 |
| `text-scroll` | fraction → local | 5.00 秒 |

**打点の列はそのまま残るので、値は正しいまま曲線だけが別の所に立つ。**
「値が合っているか」を見る検査では出ない形（表紙の画面が 9/23 に踏んだのと同じ形）。

### 費用

| 持ち方 | 畳んだあとの JSON | バイト |
| --- | --- | --- |
| `inKeys` | `1.2` | 3 |
| `emptyKeys` | `{"base":"fraction","keys":[]}` | 29 |
| `stillValue` | `{"base":"fraction","v":1.2}` | 27 |
| `onClip` | `1.2` ＋ クリップに `{"baseMemo":{"scale":"fraction"}}` | 34 |

**既定と同じ軸は覚えない**（素の数へ畳む）ので、この形が出るのは**人が軸を外した値だけ**。
ふつうのクリップ（打点なし・既定の軸）の JSON は 1 文字も増えない。
読み出しは 2.6 → **5.2 ns**（打点 2 個は 42 ns）で、打点を探さないぶん打点ありより速い。

手を入れる箇所（数えたもの。測ってはいない）:

| 持ち方 | 箇所 |
| --- | --- |
| `inKeys` | 0（ただし**軸を選ぶ口が作れない**） |
| `emptyKeys` | 1（読む所。ただし値が落ちる） |
| `stillValue` | 5（型・読む所・畳む所・置く所・軸を選ぶ口）。**どれも値の側の中** |
| `onClip` | 3。うち 1 つが**値を持ち出す口すべて**（書き忘れると黙って軸が落ちる） |

**編集の操作（`src/model/ops.ts`）は 4 通りとも 0 箇所。**

### 決めたこと

`stillValue` を既定にした（`{ base, v }`）。`onClip` は落ちる操作が 1 つで箇所も少ないが、
落ちるのが**「この寄りを別のカットにも」という短尺の編集でいちばん出る操作**で、
しかも**口を増やすたびに書き忘れが増える形**の傷なので取らなかった。

一緒に入った口:

- `setTrackBase(clip, value, base)` — **打点が 0 個でも軸を決められる。**
  打点があるときは**見た目が変わらないように時刻を写し替える**（画面にも同じ式が書いてあったので寄せた）。
- `collapseTrack(clip, value, fallback)` — 畳むときの形（既定の軸なら素の数）。
- `removeKeyAt()` が `clip` を受けるようになった（既定の軸かどうかを知るため）。

画面は `state.base` という**自分の欄をやめて、値から読む**ようになった（`baseNow()`）。
`kf-put` は軸を渡していない。**これが「画面が覚えなくてよくなった」ことの確かめ**で、
`uitest` の 6 件がそこを見ている（75 件）。

> **粗探しで 1 つ見つけた。** 畳んだ形は `Animated`（素の数か打点の列）ではないので、
> **打点 0 個 × 既定でない軸のまま編集を当てると画面が落ちた**（`keys` が undefined）。
> わざと戻して FAIL することまで確かめてある。
