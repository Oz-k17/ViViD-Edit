# lab — 試作置き場

本体（`src/`）に入れる前に、単体で動かして確かめるための場所です。

- 本体のビルド（`npm run build` / `npm run bundle`）からは完全に切り離してあります。
  ここが壊れても配布物には影響しません。
- 各試作は「判断する純粋な関数」と「見せる画面」を分けて書いています。
  本体へ持っていくときに要るのは前者だけです。
- 判断する部分を DOM から切り離しておくと、Node が `.ts` をそのまま実行できるので、
  テストがブラウザ無しで回ります（`npm run lab:test`）。ここは以降も守ってください。
- `playwright` はリポジトリの依存には入れていません（本体の配布物とは関係が無いので）。
  グローバルに入っていれば `lab:uitest` が借りて使い、無ければ飛ばします。

| 試作 | 中身 | 動かし方 |
| --- | --- | --- |
| [`auto-cut/`](./auto-cut/) | 無音カット（ジェットカット）とオートダッキング、波形表示 | `npm run lab` |

```
npm run lab            # 開発サーバで開く
npm run lab:test       # 計算の検算（合成波形・ブラウザ不要・落ちたら終了コード 1）
npm run lab:fixtures   # 試し用の素材を作る（lab/fixtures/out/、git には入れない）
npm run lab:probe      # 「どの特徴量なら声を見分けられるか」を正解付きで測る
npm run lab:bench      # その素材で「実際どれくらい効くか」を測る
npm run lab:uitest     # 画面まで通して確かめる（playwright が無ければ飛ばす）
npm run lab:typecheck  # 型だけ確認する
npm run lab:build      # 単体で配れる形にする（lab/auto-cut/dist）
```

確かめ方は 3 段に分けてあります。役割が違うので、どれか 1 つで済ませないでください。

| | 何を見るか | いつ使うか |
| --- | --- | --- |
| `lab:test` | 計算が合っているか | 手を入れるたび。数秒で終わる |
| `lab:probe` | どの手なら見分けられるか | 新しい判定を考えるとき。**実装する前に** |
| `lab:bench` | 実際どれくらい効くか | 効きに関わる変更をしたとき。**数字を記録に残す** |
| `lab:uitest` | 読み込む → 描く → 鳴らす、が繋がっているか | 画面に手を入れたとき |

試し用の素材は**種を固定して生成**しています。毎回まったく同じ音が出るので、
「昨日は 37% 削れた／今日は 41% 削れた」をそのまま比べられます。
どこでしゃべっているかも `lab/fixtures/spec.mjs` に書いてあるので、正解と突き合わせられます。

素材には**わざと意地悪なもの**（`※` 付き）が混ぜてあります。自分の手を潰しにいく素材が無いと、
「うまくいった」の中身が「自分に都合のいい素材で試しただけ」になります。
新しい判定を入れるときは、それを潰す素材も一緒に足してください。

実際、2026-09-10 に足した `music-tremolo.wav`（声と同じ速さで震える楽器だけ）は、
その日に入れようとしていた判定を**その場で壊しました**。壊れることが分かったから作り直せたので、
あの素材が無ければ「うまくいった」と書いて終わっていたはずです。

2026-09-11 の `music-wah.wav`（声と同じ速さでフォルマントが動く楽器だけ）も同じです。
その日に入れようとしていた「包絡の動きで声を見分ける」手を潰したうえ、
**いま動いている判定にも穴が開いていることを見せました**（声がゼロの素材を 7 本に切り刻む）。

2026-09-13 の `music-hats.wav`（和音の上でハイハットが刻む音楽・声なし）は、
**`music-chords.wav` とハイハットの有無だけ**が違います（和音も背景も乱数の種も同じ）。
ハイハットを足しただけで、声らしいコマの割合が 33% → **88%**、形が動いた秒数が
0.04 → **12.98 秒**（13 秒中）になり、**4 つの判定すべてを素通り**しました。
同じ日の `music-flute.wav`（息の雑音を持つ管楽器・声なし）も同じように素通りし、
さらに削減 7%（声がゼロなのに切った）という実害まで出ました。

この 2 本を足した理由は、**「雑音の粒があるか」で声を見分ける手を、手元の素材では
そもそも検証できなかった**からです。音楽の素材 6 本のうち 5 本が正弦波の和で、
雑音を持つのは打楽器 1 本だけでした。**分ける側に雑音が無い状態で「雑音があれば声」を測れば、
必ず良い数字が出ます。** それは判定の出来ではなく、素材の偏りを測っているだけです。

**意地悪なのは「声でない素材」だけではありません。** 2026-09-11（2 回目）に足した
`speech-sustained.wav`（母音を長く伸ばす声）は、まぎれもない声なのに包絡が動きません。
その日に開こうとしていたコマ単位の門を、作ったその場で潰しました（声の 6 割を切る）。
**判定を通ってほしいのに通らない素材**も、同じだけ価値があります。

2026-09-12 の `music-chords-faster.wav`（和音が 0.2 秒ごとに変わる音楽・声なし）は、
**前の回に「破れるはず」と書いて残しておいた素材**です。実際に破れました。
0.4 秒ごとの `music-chords-fast.wav` と**和音の間隔しか違わない**のに、片方は止まり、
片方は 4 つの判定すべてを素通りします。ほかを変えずに 1 つだけ変えた 2 本を並べると、
**判定が本当は何を見ていたのか**が出ます（この場合は「声かどうか」ではなく「変化の間隔」）。

### 合成の声について（2026-09-11・2 回目に作り直した）

`speak()` はもともと、倍音を 4 本重ねて音量を 4.2Hz の正弦波で揺らすだけのものでした。
**発話中ずっと倍音の重みも音程も変わらない**ので、スペクトルの上では
「トレモロのかかった楽器」とまったく同じものだったことになります。
そのせいで、包絡の動きを使う判定も、揺れの規則正しさを使う判定も、
**素材のほうが先に破れて試せない**という詰まりが起きていました。

いまは倍音列に母音の共鳴（3 つのフォルマント）を掛け、音節ごとに母音を選び直し、
音節の長さを振り、抑揚で基本周波数を動かしています。
**測った数字がおかしいときは、判定より先に素材を疑ってください。**
作り直したときに実際、過去の結論が 2 つ成り立たなくなりました（詳しくは JOURNAL の同日）。

平板だった頃の声は `makeShort` に `{ flat: true }` を渡せば作れます（乱数の消費数まで
当時と同じなので、同じ種なら 1 ビットも変わりません）。過去の数字を測り直すためのものです。

### 子音と息について（2026-09-12・2 回目に足した）

上の作り直しでも、声は**母音だけ**でした。子音も息の雑音も無いので、
**広い帯域に散る雑音の粒がまったく入っていません**。
手で考えた手がかりが 5 つとも自作の楽器の素材に負けたあとで記録を読み直すと、
破れた 5 つはどれも「音程・包絡・揺れ」しか見ていませんでした。
**本物の話し声が楽器と決定的に違うのはそこ**なので、
いちばん効きそうな手がかりを、素材が表現できないせいで一度も試せていなかったことになります。

いまは音節の頭に摩擦音（`s`・`sh`・`f`）か破裂音（`t`・`k`・`p`）を置き、
母音を鳴らしている間は薄い息の雑音を重ねています。6 つに 1 つは母音で始まります
（必ず頭に雑音がある声は、現実より都合がよすぎる）。

足したあとで測ると、**判定側の結論が 2 つ動きました**（数字は JOURNAL の同日）:

- `speech-sustained`（母音を伸ばす声）の**取りこぼしが 0% から 25% に増えた**。
  原因は息ではなく子音で、`modulation`（音節の速さ）が落ちたため。
- `tone`（音色の尖り具合）が、BGM の乗った素材で**逆向きになった**。
  本物の声は正弦波の和音より雑音的なので、息を足すと音楽のほうが「尖って」見える。
  声らしさの片方が成り立っていたのは、**雑音の無い合成音のおかげ**でした。

子音も息も無い声は `{ vowelsOnly: true }` で作れます（同じ種なら足す前と 1 ビットも変わりません）。
これは過去の数字を測り直すためだけのものではなく、
**`speech-vowels-only.wav` として一覧にも置いてあります**。ハミング・詠唱・歌の母音のように、
子音がほとんど無い発声は現実にあるので、子音に頼る判定を入れるなら
**それがこの素材を切らないこと**を必ず併せて見てください。

## 毎日の作業

このラボは、1 日 1 回の自動セッションが少しずつ広げていきます。
何をやったか・次に何をやるかは [`JOURNAL.md`](./JOURNAL.md) にすべて書いてあります。

セッションは毎回まっさらな状態で始まるので、**記録が唯一の引き継ぎ**です。
作業したら必ず追記してください。
