# ラボの定期実行を 1 回まわす

**この会話では作業しません。** 子セッションを 1 つ作って任せ、その id を 1〜2 行で報告して終わりです。

## なぜ、ここでやらないのか

理由が 2 つあります。

1. **トリガーから直接生まれたセッションは push できません**（`push blocked by git proxy auth`）。
   そこで作業すると、20 分かけたものが最後に丸ごと消えます。
   実際に 2026-09-08〜09-10 の 3 回ぶんがそうやって失われました。
   押し先つきの子を作れるのは、人と話しているこのセッションだけです。
2. ここで直接ラボ作業をすると、**この会話が作業ログで埋まります。**
   人が読みたいのは製品の話で、試作の測定ログではありません。

## 手順

### 1. 子セッションを作る

`mcp__claude-code-remote__create_session` を、次のとおりに呼びます。

| 項目 | 値 |
| --- | --- |
| `title` | `ViViD Edit ラボ（自動実行）` |
| `source_url` | `https://github.com/Oz-k17/vivid-edit` |
| `source_revision` | `main` |
| `outcome_branch` | `main` |
| `prompt` | 下の文面 |

`outcome_branch` を必ず付けること。**これが押し先で、無いと子も push できません。**

渡す文面:

```
ViViD Edit のラボを 1 回ぶん進めてください。

作業ディレクトリは `/home/user/vivid-edit`、ブランチは `main` です。
`node_modules` が無ければ先に `npm install` してください。

**手順はリポジトリの `.claude/skills/lab/SKILL.md` に全部書いてあります。
まずそれを読んで、そのとおりに進めてください。**

いちばん最初に `git push --dry-run origin HEAD:main` を打って、push が通ることを
確かめてください。通らなければ、何も作らずに「push できないので今回は作業していません」と
エラー文つきで報告して終わってください。作っても消えるだけです。

題材は `lab/JOURNAL.md` の「やることの候補」から選びます。その先頭に人の判断による
**方針と、凍結したテーマの一覧**があります。必ず読んで、凍結したものは題材にしないでください。
まだ一度も触っていない項目を 1 つ選び、どれを選んだかを報告に書いてください。

着手する前に、`git log --oneline -15` と `lab/JOURNAL.md` の最新の記録を突き合わせて、
これから作るものが未実装であることを確かめてください。

日本語で作業し、終わったら何をやって何が分かったかを日本語で短く報告してください。
`origin` への push が通らなかったときは、報告の 1 行目に必ず「push できていません」と
書いてください。
```

**文面はこれ以上長くしないこと。** 方針・凍結テーマ・確かめ方・記録の残し方は、
すべて `lab` スキルと `lab/JOURNAL.md` の中にあります。ここへ写すと、
直す場所が 2 つになって必ず片方が古くなります（2026-09-28 に配り先で同じことが起きました）。

### 2. 前回ぶんが着いているかを見る

```sh
git ls-remote --heads https://github.com/Oz-k17/vivid-edit main
```

進んでいなければ、その旨を一言添えます。**余計な調査はしないこと。**

### 3. 報告する

1〜2 行です。

- 作った子セッションの id
- 次回の予定時刻（JST 9 時 / 12 時 / 17 時のうち次のもの）
- origin が進んでいなければ、その一言

## してはいけないこと

- **ここでラボ作業をする。** 題材を選ぶ・測る・実装する、はすべて子の仕事です
- **子の作業が終わるのを待つ。** ポーリングもしません。報告したら終わりです
- **子の文面に、リポジトリにある内容を写す。** 上の理由のとおり
- **押し先を 2 つにする。** 2026-09-28 に 1 つへまとめました。配り先が古いままになるためです
