# ViViD Edit

ブラウザだけで完結する、**ショート動画（縦型）専用**のビデオエディタです。
Premiere Pro 風のマルチトラックタイムラインを持ちながら、TikTok / Instagram Reels / YouTube Shorts 向けの
縦型編集に必要なものだけを 1 画面にまとめています。

素材の読み込みも編集も書き出しも、すべてブラウザの中で処理します。**動画がサーバーに送られることは一切ありません。**

## ダウンロード

### ⬇ [**ViViD-Edit-main.zip をダウンロード**](https://github.com/Oz-k17/ViViD-Edit/archive/refs/heads/main.zip)

約 1 MB。ビルド済みのものが入っているので、展開すればそのまま使えます。
iPhone / iPad の Safari でもこのリンクから「ファイル」アプリに保存でき、
保存した ZIP をタップすると同じ場所に展開されます。

展開したあとにすることは端末で違います。

| 端末 | すること |
| --- | --- |
| パソコン | `docs/index.html` をブラウザで開く |
| iPad | `ios/ViVidEdit.swiftpm` をタップ → Swift Playgrounds が開くので ▶ で実行 |
| iPhone | **ZIP からは動かせません**（下記参照）。GitHub Pages の URL を使ってください |

**iPhone について。** Swift Playgrounds は iPad と Mac 向けで iPhone 版が無いため、`.swiftpm` を
その場で開くことはできません。また iPhone の Safari は「ファイル」アプリの中にある HTML を開いても
JavaScript を実行しないので、`docs/index.html` を展開しても動きません。
iPhone で使うには、次のどちらかになります。

- **GitHub Pages の URL で開く**（下の手順で有効化。いちばん手軽）
- **Mac の Xcode でアプリとして入れる**（カメラロールへ保存できるのはこちらだけ）

## 開き方

### パソコンで開く

ZIP を展開して **`docs/index.html`** をブラウザで開くだけです。インストールも準備も要りません。

### URL で開けるようにする（GitHub Pages）

リポジトリの **Settings → Pages** を開き、Source を **Deploy from a branch**、
ブランチを **`main`**、フォルダを **`/docs`** にして Save すると、数分後に
`https://oz-k17.github.io/ViViD-Edit/` で開けるようになります。
**iPhone から使う場合はこれがいちばん確実です。**
公開したくない場合は設定しなくて構いません（パソコンなら上の方法だけで使えます）。

### iPhone / iPad にアプリとして入れる

`ios/ViVidEdit.swiftpm` を Swift Playgrounds（iPad）または Xcode（Mac → iPhone）で開いて実行します。
くわしくは [`ios/ViVidEdit.swiftpm/README.md`](ios/ViVidEdit.swiftpm/README.md) を見てください。
ブラウザ版と違い、**書き出した動画をカメラロールへ直接保存できます**。

### 開発用に動かす

```bash
npm install
npm run dev      # http://localhost:5173
```

### コマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動 |
| `npm run build` | 型チェック＋本番ビルド（`dist/`） |
| `npm run preview` | ビルド結果をローカル配信 |
| `npm run typecheck` | 型チェックのみ |
| `npm run bundle` | ビルドして `docs/` と iOS 版へ配布物を配る |

## 自動で組む（アプリの外から）

書き起こしと素材があれば、**開けるプロジェクトをコマンドで組み立てられます。**
作るのは完成品ではなく**下書き**で、アプリで開いて「台本」から直す前提です。

```sh
npm run autoedit -- \
  --video /srv/media/配信/haishin.mp4 \
  --src 配信/haishin.mp4 \
  --transcript 書き起こし.json \
  --from 3600 --to 3660 \
  --title 'ただ喋れば\nいいってもんじゃない' \
  --out 切り抜き.vivid.json
```

できた `.vivid.json` を、アプリの **`設定` → `プロジェクトの受け渡し`** から開きます。

- **`--src` はアプリの素材フォルダから見た相対パス**にしてください。プロジェクトファイルは
  素材の実体を持たないので、ここがずれると開いた側で絵が出ません
- `--layout three` で上下に分けた 3 段に組みます
- `--style` でテロップの体裁を選べます（既定は `tv`）
- 素材の寸法と尺は `ffprobe` があれば自動で読みます。無ければ `--width --height --duration`
- 終わったら**確かめてほしい所**を出します（切り出し位置、読める長さに届かない行）。
  黙って完成扱いにはしません

組み立てる中身（`src/model/autoedit.ts`）は画面に依存していないので、**アプリの中からも外からも同じ物**が呼べます。

## 表示の切り替え（PC / スマホ）

上部バーの小さなボタン（🖥 / 📱）で、PC 表示とスマホ表示をいつでも切り替えられます。
端末判定で勝手に切り替わることはありません（初回だけ画面幅で初期値を決め、以後は選んだ設定を記憶します）。

スマホ表示では 1 カラムになり、

- プレビューが常に画面上部
- 分割・削除・テロップ追加は、キーボードなしで押せるボタン列に
- 素材 / 編集 / タイムラインは下のシートで切り替え
- シート上部のつまみを上下にドラッグして高さを変更、タップでたたむ（プレビューを最大化できます）

管理ページ（素材管理・テンプレート集・設定）も同じ切り替えに追従して 1 カラムになります。

## できること

### タイムライン（マルチトラック）

`Project > Sequence > Track > Clip` の構成で、映像 V1 / V2、テロップ T1、音声 A1 / A2 を同時に扱います。

- 素材ライブラリからタイムラインへ**ドラッグ＆ドロップ**で配置（ダブルクリックでも再生ヘッド位置へ）
- クリップの**左右端をドラッグしてトリム**（イン点 / アウト点）
- クリップ本体をドラッグして**時間軸・トラック方向へ移動**（重なった部分は上書き）
- 再生ヘッド位置で**分割**（`C`）
- **通常削除**と**リップル削除**（後続を詰める）
- **スナップ**（他のクリップの端・再生ヘッド・0 秒に吸着）
- **ズーム**イン / アウト、再生ヘッドの**スクラブ**と追従スクロール
- **複数選択**（Shift+クリック、空き領域のドラッグで範囲選択）
- **編集モード**と**範囲編集**（下の「編集ツール」）
- **Undo / Redo**（60 件以上の履歴。スライダー操作はまとめて 1 手に）
- トラックごとの表示 / ミュート切り替え

### 画面のレイアウト

素材・インスペクタ・タイムラインは、**見出しを掴んで左レール / 右レール / 下段のどこへでも移せます**。
並び順の入れ替え、レールの幅・下段の高さの変更（境目をドラッグ）にも対応していて、配置は保存されます。

- **重ねてタブにする** — 他のパネルの**見出しのあたり**（上端）へ落とすと、同じ場所に重なってタブになります。
  狭い画面でも 3 枚ぶんの場所を取らずに済みます。タブを押せば切り替わり、タブごと掴んで別の場所へ出せます。
- **要らないものは仕舞う** — 見出し右端の `×`（タブのときはタブの中の `×`）で消せます。
  戻すのは上部バーの「⊞ パネル」から。仕舞っている数もそこに出ます。

元に戻したいときは「設定 > 編集画面のレイアウト」から初期状態に戻せます。

### カットの切り替え（トランジション）

継ぎ目のアイコンをクリックすると、**ディゾルブ / フェード / スライド / ワイプ / フラッシュ**を長さ付きで選べます。
プレビューでも書き出しでも同じように合成されます。

### フレームレート

24 / 25 / 30 / 50 / 60 fps に対応しています。
読み込んだ動画のフレームレートは**入れ物（コンテナ）を直接読んで判定**するので、
そのブラウザで再生できないコーデックでも分かります。最初の 1 本を置いたときは
その値をシーケンスへ自動で取り込み、あとから食い違ったときは
シーケンス設定に「◯◯ fps に合わせる」を出します。書き出しのフレームレートは
書き出しダイアログでも選べます。

### 画づくり

- 画角 9:16 / 1:1 / 4:5 / 16:9
- **背景ぼかし（ブラーフィル）** — 横型素材を縦型に置いたときの余白を、同じ映像のぼかしで埋めます（強さ・拡大率を調整可）
- **クロップ** — 入れるとそのまま範囲指定モードに入り、**プレビューを指またはマウスでなぞって切り抜く範囲を決められます**。
  - 四隅と辺の中央、あわせて **8 つのつまみ**で大きさを、内側のドラッグで位置を変えられます
  - **縦横比の固定**（フリー / 画角 / 1:1 / 4:5 / 9:16 / 16:9）。固定中は角でも辺でも比率が崩れません
  - 素材の**端と中心に吸い付きます**（比率を固定しているあいだは形が崩れないよう吸着しません）
  - 選んだところは元の場所に残るので「囲った以外が消える」見た目になり、「画角いっぱいに」を押せば縦横比を保ったまま寄れます
  - 完了したあとも、切り抜いた絵を置く枠を**四隅のつまみでリサイズ**できます（比率は保たれるので絵が伸びません）
  - `Enter` / `Esc` で完了。数値での微調整も残してあります
- 不透明度・スケール・位置・回転・速度（0.25〜3 倍）・前後のフェード
- **エフェクトタブ** — 明るさ / コントラスト / 彩度 / モノクロ / セピア / 色相 / ぼかし / 反転を、強度付きで重ねがけ。ルックのプリセットも 6 種
- **エフェクトを時間で効かせる** — 掛けたら最後まで掛かりっぱなし、をやめました。
  エフェクトごとに **ずっと / 頭だけ / 一瞬 / 入ってくる / 抜けていく** を選べます。
  - 「頭だけ」はセグメントの頭で一度効かせてすぐ戻す形（**0.25 秒のズーム**がこれで作れます）
  - 「一瞬」は決めゼリフの所で瞬かせる形
  - いつから / どれだけ / 立ち上がり / 抜け は秒で細かく動かせます
  - 抜けた所は**素通しに戻ります**（明るさは強度 0 が素通しではないので、型ごとの素通しの値へ戻します）
  - 時間を指定しなければ、これまでどおり一定で掛かります。保存済みのプロジェクトは変わりません

### 台本（自動で組んだものを、読みながら直す）

左のレールの **「台本」** タブに、プロジェクトの中身が**読み物の形**で並びます。
テロップ・音・映像に分かれていて、上から下へ「どの言葉が、いつ、どの順で出るか」が読めます。

- **その場で書き換えられます。** 文字を打てば、タイムラインにもプレビューにもすぐ反映されます
- 行を押すと、そのクリップを選んで**頭出し**します。形を見ながら直せます
- **読むには短すぎる行に ⚠ が出ます**（文字数 × 0.15 秒 + 0.3 秒が目安）
- 要らない行はその場で消せます

自動で組んだものを直すための場所です。タイムラインの上で 1 本ずつ選ぶより手数が少なくて済みます。

### 編集ツール（タイムライン）

タイムライン上部の「編集ツール」の行で、ドラッグの意味を切り替えます。Premiere のツールと同じ考え方で、キーでも切り替えられます。

| モード（キー） | 端をドラッグ | クリップをドラッグ |
| --- | --- | --- |
| 通常（`V`） | トリム（空いた所は残る） | 移動 |
| リップル（`B`） | トリム＋**後ろのクリップも一緒に動く** | 移動 |
| ロール（`N`） | **隣のクリップとの境目だけ**が動く（全体の尺は変わらない） | 移動 |
| スリップ（`Y`） | トリム | **位置と尺はそのまま、使う場面だけをずらす**（右へドラッグ → 手前の場面へ） |
| スライド（`U`） | トリム | **位置を動かし、前後のクリップが伸び縮みして埋める** |

- **押している間だけ切り替え**: 端は `Alt` でリップル・`Ctrl/⌘` でロール、クリップ本体は `Alt` でスリップ・`Ctrl/⌘` でスライド
- 素材の頭・終わりを越えるトリム、0.1 秒より短くなる操作は、限度で止まります
- **挿入配置**（`J`）: オンの間、素材を置くと既存のクリップを上書きせず、後ろへ送って挿入します（素材パネルのダブルクリックは V1 / A1 へ）
- **In / Out**（`I` / `O`、消すのは `Ctrl/⌘+Shift+X`）を打って、**リフト**（`;`: 取り除く・隙間が残る）か**抽出**（`'`: 取り除いて詰める）
- **隙間を詰める**（`Alt+Delete`: 再生ヘッドの位置）、**全トラック分割**（`Ctrl/⌘+K`）
- **前後の編集点へ移動**（`↑` `↓`）、**ナッジ**（`Alt+←` `Alt+→` で 1 フレーム、`Shift` で 5 フレーム。いまのモードの動かし方で動く）、**全クリップ選択**（`Ctrl/⌘+A`）
- スマホ表示では、ツールの行が横スクロールになります

### 素材の複数選択と並び替え

- **選ぶ**: クリックで 1 つ、`Ctrl/⌘`+クリックで足し引き、`Shift`+クリックで範囲（起点からいま見えている並び順で数えます）、`Ctrl/⌘+A` で全部、`Esc` で解除
- **一括操作**: 選ぶと出る帯から、ビンへまとめて移す・まとめて削除（確認あり）・タイムラインへ置く。`Delete` で削除、`Enter` でタイムラインへ
- **ドラッグ**: 選んだ素材をつかむと、**選択ぜんぶ**を運びます（タイムラインへは隙間なく並べて置く、ビンへはまとめて移す）。選んでいない素材をつかんだら、その 1 つだけ
- **素材管理ページ**は、各行のチェックボックスで同じ選び方（`Shift` で範囲）。「表示中をすべて選ぶ」もあります
- **並び替え**: 追加順（新しい順）・名前（`clip2` が `clip10` より前になる自然順）・長さ・サイズ・種類（動画 → 画像 → 音声）。もう一度同じ項目で昇順／降順。選んだ並びは覚えています
- 素材パネルはページ送りをやめ、一覧を並べて、多いときは「さらに表示」で足します

### 素材のビン（ツリー）

素材ライブラリは、フォルダを**入れ子（ツリー）**にして整理できます。エディタの素材パネルと `#/media-library` で同じ操作です。

- **新しいビン** — 選んでいるビンの中に作ります（何も選んでいなければ最上位）。名前は Enter で確定、Esc で取り消し
- **移す** — 素材もビンも、ドラッグして別のビンへ。ビンを動かすと、中の素材と子のビンもまとめて付いていきます（自分の中へは移せません）
- **名前を変更**（F2）— 中の素材の所属も一緒に直ります。同じ場所に同名は作れません
- **削除** — **素材は消しません。**中身は一つ上のビンへ上がります（最上位なら、サブ構造を保ったまま最上位へ）
- **キーボード** — ↑↓ で移動、→ で開く（もう一度で子へ）、← で閉じる（もう一度で親へ）
- **検索** — 名前とビンのパスの両方を、空白区切りの AND で探します。検索中はビンを問わず全体から探します
- **NAS** — NAS のフォルダ階層が、そのままビンの階層になります
- 「未分類」「効果音」「絵文字」はアプリが使うので、名前変更・移動・削除はできません（中にビンを作るのは自由）

内部では、素材の `folder` を `映像/配信1` のような `/` 区切りのパスとして読んでいます。
`/` を含まない従来の名前はそのまま最上位のビンになるので、保存済みの素材はそのまま使えます。
空のビンとツリーの開き具合は、このブラウザの localStorage に置きます（消えても素材は失われません）。

### 自動解析（試験的）

映像クリップを選ぶと、インスペクタの下に **「自動解析（試験的）」** が出ます。
ラボで「実用ラインに乗った」と判断した 3 つを、本体で試せるようにしたものです。
押したあとは **Undo 1 回で戻ります。**

- **シーンで分割** — カットの切り替わりを見つけて、場面ごとにクリップを割ります
- **被写体を追って切り出す** — 横長の素材から縦型を切り出すとき、枠を被写体に合わせて置きます。
  本体は時間で変わる値（キーフレーム）を持っていないので、**枠が止まった区間に畳んで、区間ごとにクリップを割ります**
  （区間の境目で枠がぽんと動きます）。縦長の素材から 1:1 を切るときは縦の軸で同じことをします
- **表紙の候補** — 表紙に使えそうなコマを 3 枚選んで並べます。「ここへ移動」と「画像で保存（PNG）」ができます

**数字はすべて合成した試し素材で測ったものです。**本物の配信アーカイブでは測っていません。
目安（ラボの測定）: シーン検出は見つけた率 92.3% ／ 当てた率 98.0%、
リフレームは被写体を枠に入れた率 95.2%（区間に畳んだあと。畳む前は 95.8%）、
表紙は駄目なコマを選んだ率 0.0%。
実機では、カット 3 回の動画を 3 か所で割り、動く被写体の動画を 4 区間に割って確かめています。

判断の部分は `src/analysis/` にあります（ラボの原本とずれていないことを `npm run test:model` が見ています）。
写しの扱いは [`src/analysis/README.md`](./src/analysis/README.md) に。


### 音量を整えて書き出す（試験的）

書き出しダイアログの **「音量を整えて書き出す」** をオンにすると、書き出す音を次の順で仕上げます。

1. 全体のラウドネスを測る（LUFS）
2. **-14 LUFS** へ倍率 1 つで揃える
3. 真のピークが **-1 dBTP** を超えるところだけリミッタで均す（深さは最大 6 dB）

- 高精度書き出し（WebCodecs）のときだけ使えます。実時間収録の保険経路では音を後処理できないため、スイッチは無効になります
- 無音など測れない素材は、そのまま書き出します
- 結果（前後の LUFS・ピーク）は書き出し完了の画面に出ます
- クリップごとの音量合わせ・無音カットは、まだ本体には入れていません
- 数値は合成した波形で検査したものです。本物の配信音声での聞こえ方は未検証です

### テロップ

- 12 種のスタイルプリセット
  （字幕・見出し・白ヌキ帯・ネオン・タイプ・3層フチ・**テレビ風**・**ざぶとん**・**立体**・見出し（幅いっぱい）・コメントカード・ポップ）
- フォント 7 種、サイズ、太さ、フチ（2 層）、影と影の落とす向き、背景帯、揃え、折り返し幅
- **入場アニメーション** — ポップ / フェード / 上下左右スライド / ズーム / バウンス / タイプライター / **ワイプ** / **ブレ**
- プレビュー上で直接ドラッグして位置調整
- タイムライン上のクリップなので、**表示したいカットに合わせて開始と長さを決められます**
- **絵文字タブ** — アップロードした画像を、文字と同じようにテロップの中へ挿入できます（削除・並べ替えも普通の文字と同じ）

### 書き起こしの取り込み

文字起こし（SRT / WebVTT / Whisper の JSON）を選ぶと、**時刻付きのテロップが一気に並びます**。
文字起こしそのものはこの道具の外（faster-whisper など）で作る前提です。

- 長い行は、指定した文字数で**読める単位に割ります**。単語の時刻があればそこで、無ければ文字数で按分します。
  割る位置は折り返しと同じ規則（禁則・助詞・字種の変わり目）なので、語の途中で切れません
- 短すぎる行は、**次の行にぶつからない範囲で伸ばします**（1 文字 0.15 秒 + 0.3 秒が目安）。
  伸ばしきれなかった行は件数で知らせます
- 書き起こしに話者が入っていれば、出てきた順に**話者 1 / 2 の色**を当てます
- 素材の途中から起こした場合のために、**先頭のずれ**を秒で足せます

#### 音から直接起こす（アプリの中だけで完結）

タイムラインの映像・音から、**そのまま文字起こしできます**。ブラウザの中で Whisper を回すので、
外へ音を送りません。

- 重い部分（transformers.js・onnxruntime・モデル）は**同梱していません**。
  `npm run bundle` を通すと `docs/whisper/` に駆け出し部分（1.8KB）だけが入り、
  部品は CDN から、モデルは Hugging Face から、押したときに取ります
- **ネット無しで回したいとき** — `npm run whisper:pack` で部品一式を `docs/whisper/` へ写し、
  モデルを `docs/whisper/models/<作者>/<名前>/` に置いて、
  画面の「手元に置いたモデルだけを使う」を入れます（合計 約 100MB + モデル）
- **GPU（WebGPU）があれば桁違いに速い**です。無ければ CPU でも回りますが、
  `deploy/nas/nginx.conf` の COOP / COEP を入れると CPU でもかなり速くなります（注意書きあり）
- **iOS 版（`file://`）では使えません。** その場合は理由を出して、取り込みのほうへ案内します

**聞き取りを良くするために、渡す前と後ろでやっていること**

whisper は声の無い所を渡されると、黙るのではなく**言葉を作ります**。無音や音楽の上に
「ご視聴ありがとうございました」が乗るのはこれが原因です。そこで、

- **渡す前** — 低い所を落とし（80Hz のハイパス）、音量を揃え、**声のある所だけを繋いで**渡します。
  繋いだぶん時刻がずれるので、戻すための対応表を持っておいて、返ってきた行を元の時刻へ戻します
- **回すとき** — 直前の出力を次の手がかりにしません（ここを繋ぐと、いちど言葉を作り始めたときに
  同じ行が何十行も並びます）。「丁寧に起こす」を入れると探す道を 5 本に増やします
- **返ってきた後** — 癖の分かっている幻だけ落とします。決まり文句、直前と同じ行の繰り返し、
  同じ字が 6 つ以上続くもの、1 秒に 25 文字を超えるもの。**何をいくつ落としたかは毎回出します**
  （黙って捨てると、消えた言葉を探すはめになるので）

| モデル | 日本語 |
| --- | --- |
| large-v3-turbo | いちばん良い。ただし重い（GPU 推奨） |
| small | ぎりぎり使える |
| base | 粗い |

### 音

クリップごとの音量とミュート、素材の繰り返し（ループ）、フェードイン / アウト、トラック単位のミュート。
**効果音プリセットを 8 種同梱**（ピロリン・通知音・ポン・シュワ・カシャ・タッ・キラキラ・ブー）。
音源ファイルを同梱する代わりに WebAudio でその場で合成しているので、リポジトリは軽いままです。

### 素材ライブラリ

フォルダ分け、ページ送り（枠に収まらない分は次のページへ）、名前変更、削除。
素材は IndexedDB に保存されるので、**ページを移動してもリロードしても残ります**。

### テンプレート

テロップのスタイルと、タイムライン構成（動画レイアウト）をテンプレートとして保存し、ワンクリックで呼び出せます。

### 書き出し

**アスペクト比（9:16 / 1:1 / 4:5 / 16:9）と画質（1080p / 720p / 480p）を選んで**、タイムライン全体を 1 本の動画にします。
編集時と違う画角を選ぶと、その解像度でレイアウトし直して書き出します。
形式は MP4（H.264 + AAC、対応ブラウザ）または WebM（VP9 + Opus）。

## 動作環境

Chrome / Edge を推奨します（H.264 の MP4 で書き出せます）。Safari 17 以降でも動きます。
Firefox でも編集・書き出しはできますが、出力は WebM になります。

## 仕組み

映像の組み立て（合成・再生・音づくり）はブラウザ標準の API だけで書いています。
書き出しだけは、コーデックの詰め込み（多重化）に [mediabunny](https://mediabunny.dev/) を使っています。
ffmpeg.wasm のような重量級の変換エンジンは持ち込まず、エンコード自体はブラウザの WebCodecs に任せています。

| 役割 | 実装 |
| --- | --- |
| データモデル | `src/model/types.ts` — Project / Sequence / Track / Clip。JSON 化できるものだけで構成し、履歴・テンプレート・保存に載せられる |
| タイムライン操作 | `src/model/ops.ts` — 配置・移動・トリム・分割・リップル削除・スナップ。`src/model/editOps.ts` — 挿入・リフト・抽出・隙間詰め・リップルトリム・ロール・スリップ・スライド・編集点。`src/model/editModes.ts` — モードごとのドラッグの解釈。すべて「新しい Sequence を返す」純粋関数 |
| 合成 | `src/engine/renderer.ts` — 1 フレームをキャンバスへ描く。プレビューと書き出しで同じ関数を使うので見た目がズレない |
| クロップ枠 | `src/engine/crop.ts` — つまみの当たり判定と、掴んで動かしたときの計算。0〜1 の割合ではなく画面上の矩形で計算する（割合のままだと比率固定も吸着も素材の縦横比ごとに歪む） |
| 再生 | `src/engine/player.ts` — 鳴っている `<video>` / `<audio>` 自身の時計を正としてタイムラインの時刻を逆算する。壁時計を正にすると必ずズレが溜まり、その補正が速度の揺れや音切れになって出るため。基準の位置が進んでいないフレーム（カット直後のデコーダ起動待ちなど）だけは壁時計に任せ、繋ぎ目で時刻が固まらないようにしている |
| 音 | `src/engine/audio.ts` — WebAudio のミキサ。同じグラフから書き出し用のストリームを取り出す |
| 効果音 | `src/engine/sfx.ts` — OfflineAudioContext で合成して WAV に書き出す |
| 書き出し | `src/engine/offline-export.ts` — WebCodecs で 1 コマずつデコード → 描画 → エンコード。実時間から切り離してあるのでコマ落ちしない |
| 書き出し（保険） | `src/engine/exporter.ts` — WebCodecs が無い環境向けに、実時間で再生しながら `MediaRecorder` で収録する旧方式も残してある |
| 尺の補正 | `src/engine/webm.ts` — `MediaRecorder` の WebM には尺が書かれないので、EBML を最小限だけ書き換えて埋める |
| パネル配置 | `src/components/editor/PanelDock.tsx` — 見出しを掴んでパネルを置き場のあいだで動かす。重ね（タブ）と仕舞う操作もここ。落とし先は番号ではなく**まとまりの id** で指す（掴んだ側を抜くと並びが詰まって 1 つずれるため）。Pointer Events なのでタッチでも同じに動く |
| 状態 | `src/store/editor.tsx`（編集内容と履歴） / `src/store/app.tsx`（設定・テンプレート・パネル配置） |
| 素材の実体 | `src/engine/media.ts` — 取り込み（Blob を IndexedDB に）と参照（NAS の URL を相対パスで）の 2 通り。外向きは `url` に揃うので、再生・書き出し側は区別しない |
| 共有フォルダ | `src/engine/library.ts` — NAS の一覧の取り方。nginx の JSON autoindex → HTML 一覧 → `media.json` の順に試す（NAS ごとに何が出せるか違うため） |
| 受け渡し | `src/engine/project-file.ts` — プロジェクト + 参照素材の在り処を 1 ファイルに。運べない取り込み素材は名前を控えて知らせる |
| iOS 版 | `ios/ViVidEdit.swiftpm` — WKWebView で Web 版を表示し、保存だけネイティブで受け持つ |

描画座標は常に「シーケンス座標（例 1080×1920）」で計算し、プレビューと書き出しの解像度差はキャンバスのスケールだけで吸収しています。

## NAS に置いて、何人かで使う

社内の NAS に置けば、**URL を 1 つ配るだけ**で iPad でも PC でも使えます。
更新は NAS のファイルを差し替えるだけで、全員に配り直す必要がありません。

肝は **アプリと共有素材を同じ Web サーバから配る**ことです。別のポートや別のホストに分けると、
ブラウザから見て別オリジンになり、素材の読み込みが CORS で止まります。

そのぶん、次の 2 つができるようになります。

- **共有素材を参照で使う** — 素材パネルの「共有」から NAS のフォルダを覗いて、
  **コピーせずに URL 参照**として追加できます。各自のブラウザの保存枠を食いません。
- **プロジェクトを人に渡せる** — `設定 > プロジェクトの受け渡し` からファイル 1 個で書き出せます。
  素材は**在り処だけ**が入るので、同じ共有フォルダが見える人ならそのまま開けます。
  取り込んだ（ファイル選択で入れた）素材は端末の中にしか無いので運べません。書き出すときに名前を知らせます。

nginx と docker compose の一式、UGREEN NAS（UGOS Pro）での手順、外から使うための
Cloudflare Tunnel 版は [`deploy/nas/README.md`](./deploy/nas/README.md) にあります。

**配るときは https を用意してください。** `http://` だとブラウザが「安全なコンテキスト」と
みなさないため WebCodecs が使えず、書き出しが 1 コマずつではなく実時間の録画に落ちます
（遅い・コマ落ちする・ファイルが数倍）。編集とプレビューは動くので気づきにくく、
書き出しの画面にも注意を出すようにしてあります。

同時編集はできません。共有されるのは素材だけで、プロジェクトと設定は各自のブラウザの中です。

## 試作置き場（lab/）

本体に入れる前の試作は [`lab/`](./lab/) に置いてあります。本体のビルドからは切り離してあるので、
ここが壊れても配布物には影響しません。

- [`lab/auto-cut`](./lab/auto-cut/) — 無音カット（ジェットカット）・オートダッキング・波形表示（`npm run lab`）

### 手元で触る

ビルド済みのものを `docs/lab/` に同梱してあります。**何も入れずに、ブラウザで開くだけ**で触れます。

- 公開しているなら `https://<ユーザー名>.github.io/<リポジトリ名>/lab/`
- リポジトリを落としたなら `docs/lab/index.html` をダブルクリック（`file://` でも動きます）

音声でも動画でも読ませられます（音だけを見ます）。処理は全部ブラウザの中で完結し、どこにも送りません。
画面の「テストを実行」を押せば、計算の検算もその場で回せます。

開発しながら触るなら `npm run lab`（Vite の開発サーバ）。

### 確かめ方

3 段に分けてあります。`npm run lab:test`（計算が合っているか）、
`npm run lab:bench`（実際どれくらい効くか）、`npm run lab:uitest`（画面まで繋がっているか）。
試し用の素材は `npm run lab:fixtures` で生成でき、種を固定してあるので前後の数字がそのまま比べられます。

何をやったか・次に何をやるかは [`lab/JOURNAL.md`](./lab/JOURNAL.md) に記録しています。

## 制限

- **プレビューが重いとき**は、設定の「プレビューの画質」を下げられます。ただし実測では
  4K 素材でも縮小描画は 1 フレーム 1.2ms（60fps の予算の 7%）しかかからないため、
  効果は限定的です。重さの主因は動画のデコードそのものなので、素材が重い場合は
  あらかじめ解像度を落としたものを読み込むのが確実です。
- **書き出しは 1 コマずつ処理します。** 実時間の録画ではないので、端末が遅くてもコマ落ち・音切れは起きません。
  かかる時間は素材の重さ次第で、動画の長さより短いことも長いこともあります。タブは開いたままにしてください。
  WebCodecs が使えない古いブラウザでは、従来の「実時間で録画する」方式に自動で切り替わります（この場合は
  端末が重いとコマ落ちすることがあります）。
- 同じトラック上でクリップを重ねることはできません（重なった部分は上書きされます）。トランジションは継ぎ目に設定する方式です。
- 言語切り替えは主要なラベルのみ英語化しています（未訳の箇所は日本語のまま表示されます）。
- 素材は IndexedDB、編集内容と設定は localStorage に保存されます。ブラウザのデータを消すと失われます。
- 保存キーはアプリ名に合わせて `vivid.*` / `vivid-edit` に変えてあります。旧名（`tateyoko.*`）で
  保存されていた素材・プロジェクト・設定・テンプレートは、初回起動時に自動で引き継がれます
  （引き継いだあと旧データは片付けます）。
- ビルドは ES モジュールではなく単一の古典スクリプトとして出力しています。
  `file://` から開いた場合と iOS 版の WKWebView では、ES モジュールが CORS で読み込めず
  画面が真っ白になるためです。
