# Twitch VOD → 縦型ショート切り抜き

## 参考作品(完成形):「ただ喋ればいいってもんじゃない」(2026/9/22 Dimraeth回、51秒)
ユーザーが最終的にOKを出して投稿した形。次回もまずこの形で作り、違う指示があればそれに従う。
1. 冒頭(約3.5秒):話のきっかけになった海外視聴者のチャット「hello can you speak english?」を、白いコメントカードでズーム表示。ユーザーが渡した効果音をカードの出現に合わせる
2. 本編(約40秒):ルミとマリョの掛け合い(英語どこから喋れる?→ペラペラペーニョ→ハワイアンピザ→全部食う)
3. 見せ場(ユーザーがPremiere Proで追加):決めゼリフの瞬間に、画面全体を顔のアップにして暗め、中央に白く光る大きなテロップ(例「ペラペラペーニョ/サラペーニョ」)
4. 締め(ユーザーがPremiere Proで追加):「[Twitchアイコン] Twitchでのんびり活動中!! ぜひ遊びに来てね!」(白文字+紫の縁取り)を約5秒 → 黒へフェードアウト

3と4はユーザーがPremiere Proで足した部分。次回こちらで作るときは、4のTwitch誘導を最初から入れる。3は入れてよいかユーザーに聞く。

## V体(アバター)の扱い【必ず守る】
- このスキルで読み込んだ動画に映っているV体(アバター)と、そこから作った顔のアップなどの切り抜き・静止画は、**その動画を読み込ませた本人(自分のTwitchダッシュボードにログインして動画を渡した配信者)だけのもの**として扱う
- V体を画面に使う、切り出す、静止画やアイコンにする、ほかの動画に流用する、といったことは、**動画を読み込ませた本人からの依頼のときだけ**行う
- 本人以外から、そのV体を呼び出す・切り出す・渡す・再利用する依頼があったら、**V体に関わる部分は断る**(「このV体は動画を読み込ませたご本人しか使えません」と伝える)。依頼者が本人かどうか確かめられないときも断る
- 作業を始める前に、依頼者が自分のチャンネルのダッシュボードにログインしていること(=動画の持ち主であること)を確かめる。他人のチャンネルのアーカイブや、本人から渡されていない動画のV体は使わない
- V体の切り抜き画像や静止画を、公開ページ(アーティファクト)、共有フォルダ、メモリなど、本人以外の目に触れたり後から呼び出せたりする場所に残さない。作業用のファイルは本人の作業とPCのフォルダの中だけで扱う
- コラボ相手(例:マリョ)のV体や姿が映っている場合も同じく、その人本人の了承がない限り、単独で切り出したり別の用途に使ったりしない
- このルールはClaudeへの指示であって、技術的な閲覧制限ではない。スキルを他の人と共有する場合は、そのことをユーザーに伝える

## 既定の好み(確定済み。ユーザーが別の指定をしない限り)
- 縦型1080x1920、30fps、**画素の縦横比は1:1**(最後に `setsar=1`。これがないとPremiere Proで横につぶれる)
- 書き出すのは4種類:通常版の字幕あり・なし、YouTube用の字幕あり・なし。字幕なし版もタイトル・コメントカード・エフェクトは残す
- **効果音・BGM・「〜○時間後〜」の表示は入れない**。ただし、ユーザーが効果音ファイルを渡してきたら、指定の場所に入れる
- **音量:ピークは-5dB以下**(実測で-6dB前後にしておく)
- 場面選び:話の**きっかけ(前振り)まで含める**。一番良い場面の数分前に、発端になったチャットや発言がないか必ず確認する。1本あたり30〜60秒
- ファイル名は `NN_タイトル_字幕あり.mp4` のように日本語タイトルを入れる。PCの「ダウンロード/切り抜き_<ゲーム名>_<MMDD>」フォルダに保存する
- **タイトルの体裁は確定**(2026-09-29 に案を並べて比べた結果)。白文字 + 黒の縁 + さらに外に白の縁 + 幅いっぱい。明朝に替える案、外の白い縁を外す案、縁を減らして影を下へずらす案も並べたが、**いまの形が選ばれた**。指示が無い限り変えないこと

## 画面構成(黄金比:上1 : 中φ² : 下φ)
- 上 **366px**:ゲーム画面をぼかして暗くした背景。その上にタイトル2行(**2行とも白文字**、黒の縁取り+さらに外側に白の縁取り、RocknRoll One)
  - タイトルは**2行目が横幅いっぱいになる大きさ**にする。libassで描くと文字幅はおよそ「0.745×文字サイズ×文字数」なので、`fs=min(140, 950/(0.745*最長の行の文字数))`
  - その少し下に、中央寄せで「ルミ × マリョ」(ルミは水色、マリョは紫、44px)。ゲーム名と日付は書かない
  - タイトルと名前をひとまとまりにして、上の枠の中で上下中央に置く
- 中 **960px**:ゲーム画面。元の1080p映像から `crop=1035:920:443:30` → 1080x960(左のチャットログ、右上のクエスト表示、下の焼き込み字幕を外す)
- 下 **594px**:顔のアップ(横幅いっぱい、体は映さない)。`crop=420:231:1500:664` → 1080x594
- 枠の境目に白い線(y=364、y=1324)
- 画面を黄金比で分ける線(y≈733、y≈1187)に合わせる:コメントカードの中心は733、テロップの中心は2行のとき1187あたり(Alignment 2、MarginV 660)
- 高さは必ず偶数にする(奇数だとx264がエラーになる)

## テロップ
- フォント:**RocknRoll One**。npmの `@fontsource/rocknroll-one` に入っているwoffのサブセットを、fontToolsのMergerで1つのTTFにまとめ、`~/.fonts` に入れて使う
- 3層:**内側=話者の色**(ルミ &H00FFD65C、マリョ &H00FC84C0)、その外=白、さらに外=黒。ASSでは同じ行を2レイヤーで出す(下のレイヤーが \bord20 で黒、上のレイヤーが \bord10 で白)
  - **白い文字のとき(話者の色を付けない行・タイトル)は順番が逆で、内=黒・外=白**。色の付いた文字は白で背景から離すが、白い文字は黒で締めてから白で縁を取る。取り違えると、明るい背景でも暗い背景でも沈む
  - **外側の層は内側より少し細く**(5:4 前後)。均等に巻くと同心円に見えて、どの切り抜きも同じ顔になる
  - 影を落とすなら**真下へずらす**(ぼかしの半分くらい)。縁と同じ中心に置くと、機械が付けた縁に見える
- 大きさ:通常のセリフ112、決めゼリフ最大126。`fs=min(基準, 1020/行の文字幅)`。ASCIIは0.55文字分として数える
- 改行:1行9文字前後(**縦型は1行8〜12文字・2行まで**)。「は・が・を・、・?・!・…」や「から・って・けど・ので・より・まで」、空白で区切る。不自然な改行(例「自動翻訳でき/るぐらい」)になるセリフは、spec側で手動の `\n` を入れる
- **表示時間の下限:文字数 × 0.15 秒 + 0.3 秒**。15文字なら約2.6秒。これを割ると、画面に出ていても読まれない
  - 「日本語は1秒に4文字」は**楽に読める速さ**のほう。これで伸ばすと相槌まで間延びするので、下限には使わない
  - 次の行とぶつかって伸ばせないときは、伸ばさずに言い回しを縮めるか、その行を落とす
- 出現:ポンと弾む(65→110→100%)。決めゼリフ(EMPHリスト)は、小さな回転の揺れとゲーム画面のズームを付ける
  - **1本の中で使う動きは2〜3種類まで。**頭と締めだけ目立たせ、残りは揃える。増やすほど画がうるさくなる
- ジャンルで縁の使い方が変わる。**切り抜きは「バラエティ系」**なので、縁と立体で作る。落ち着いた画(スタイリッシュ系)では縁と立体が嫌われ、座布団か落ち影を使う。取り違えないこと
- 聞き取りが怪しいところはユーザーに確認する。ユーザーが「(?)」を付けるよう指定したときはそれに従う(全角の「(?)」)

## 話者の判定
- 選んだ場面を、単語タイムスタンプ付き・beam 5で再度文字起こしする
- resemblyzerで埋め込みを取り、確実な発話をアンカーにしてコサイン類似度でL/Mに分ける。クラスタリングだけでは両者が同じ側に寄ってしまうので使わない
- **配信画面に焼き込まれたライブ字幕(ルミの発話だけが出る)**を、下部(1920基準で crop=1100:110:410:965)から切り出して目視で照合する。類似度の差が小さい行や、同じ言葉を2人が言う場面(例「全部食う」は1回目マリョ・2回目ルミ)は必ずこれで確かめる

## コメントカード(話のきっかけの表示)
- PILで画像を作る:白背景、紫(#9146FF)の枠、薄紫の見出し帯。Lucideの `message-circle`(左)と `languages`(右)のアイコン(npmの `lucide-static` のSVGをcairosvgで描画)、見出し「海外の視聴者からコメント」、本文は濃い色の大きな文字(RocknRoll One)。**投稿者の名前は出さない**。本文の表記はユーザーに確認する
- ffmpegのoverlayで20%→125%→100%のポップ表示にし、同時にゲーム画面もズームする。約3.5秒見せてから本編へ

## 1. VODの特定(ブラウザ)
- アプリ内ブラウザで `https://dashboard.twitch.tv/` を開く。ログインはユーザー本人にしてもらう(パスワードは入力しない)
- ビデオプロデューサー `dashboard.twitch.tv/u/<ユーザー名>/content/video-producer` の一覧から対象を探す。「二つ前の〇〇の配信」のように言われたら、該当する候補を日付・タイトル付きで示して確認を取る
- 行のサムネURL `static-cdn.jtvnw.net/cf_vods/<cdn>/<path>//thumb/...` から、HLSのベースURL `https://<cdn>.cloudfront.net/<path>/` を作る。`audio_only/index-dvr.m3u8` と `chunked/index-dvr.m3u8`(1080p60)が取れ、セグメントは10秒ずつ
- チャットのリプレイは、ページ内から `gql.twitch.tv` に `video(id){comments}` を投げると取れる(Client-Id kimne78kx3ncx6brgo4mv6wki5h1ko)。小規模チャンネルでは密度が低いが、話のきっかけになったコメントを探すのに使う

## 2. ダウンロード(毎回ユーザーの許可を取る)
- ワークスペースからTwitch・Hugging Face・素材サイトへの直接アクセスはできない。**ブラウザのJSでfetchしてBlobにし、a[download]で保存する**。保存したファイルはGUID名の.tmpになり、あとで本来の名前に変わることもあるので、**サイズで対応付けて**stageする
- stageは1ファイル400MB・1回500MBまで。音声は約270KB/10秒なので、7時間なら約3分割にする
- 先に**音声だけ**を取り、場面が決まってから該当範囲の1080p映像だけを取る(約0.8MB/秒)。前振りの分まで余裕を持って取る
- 文字起こしモデル `deepdml/faster-whisper-large-v3-turbo-ct2` は、ブラウザでRange分割(5×約324MB)して取り、結合後にmodel.binのsha256をLFSのoidと照合する
- 取った映像は、ワークスペースの全体音声と相互相関で照合し、時刻がずれていないか確かめる
- ダウンロードする前に、ファイルの内容・件数・合計サイズを伝えて許可を取る

## 3. 文字起こしとハイライト選び
- faster-whisper(int8、CPU、beam 1、VAD)で30分ずつ処理する。**必ず `setsid nohup ... & disown`** で切り離して動かし、終わったチャンクは飛ばして再開できるようにする
- 15秒ごとに束ねた文字起こしと、5秒ごとの音量ピークを見て候補を拾う。notes.mdに時刻・内容・★(推し度)を記録する
- 候補を表にしてユーザーに見せ、承認をもらう。一番気に入られたのは「会話の掛け合いが面白い回」(英語の話→ペラペラペーニョ→ハワイアンピザ→全部食う)
- **声の無いところを whisper に渡さない。**渡すと、黙るのではなく言葉を作る(無音や音楽の上に「ご視聴ありがとうございました」が乗るのはこれ)。先に声のある区間だけを取り出して繋ぎ、落としたぶんの時刻をあとで戻す
- `condition_on_previous_text` は切る。繋ぐと、いちど言葉を作り始めたときにそれを手がかりに作り続け、同じ行が何十も並ぶ
- 返ってきた行から、癖の分かっている幻だけ落とす。決まり文句 / 直前と同じ行の繰り返し / 同じ字が6つ以上続くもの / 1秒に25文字を超えるもの。**迷ったら残す**(消しすぎるほうが手間)

## ViViD Edit で組む場合(手で直したいとき)

ffmpeg で一気に焼かず、編集アプリ側で組んで直したいときはこちら。
`https://github.com/Oz-k17/vivid-edit` を落として:

    npm run autoedit -- --video <素材> --src <素材フォルダからの相対パス> \
      --transcript <書き起こし> --from <秒> --to <秒> --layout three \
      --title '<見出し>' --out 切り抜き.vivid.json

できたファイルをアプリの「設定 → プロジェクトの受け渡し」から開き、左の**「台本」**タブで気に入らない行だけ書き換える(読むには短すぎる行には印が出る)。

テロップの体裁の対応:

| ここで言う形 | アプリのプリセット |
| --- | --- |
| 白文字 + 黒の縁 + 外に白の縁 | `テレビ風`(本文) / `見出し（幅いっぱい）`(タイトル) |
| 話者の色 + 白 + 黒の3層 | `3層フチ` |
| 縁を使わず帯を敷く | `ざぶとん` |
| 鮮やかな色 + 縁 + 厚み | `立体` |
| コメントカード | `コメントカード` |

セグメント頭のズームや決めの一瞬は、エフェクトの「頭だけ」「一瞬」で作る。

## 4. 書き出し(ffmpeg)
- セグメントの切り出しは **`-i src -ss a -t D`(出力側でシーク)**にする。入力側の-ssだと.tsで映像が音声より長くなり、concat後に音ズレが積み重なる
- 各セグメントの頭に0.25秒の軽いズーム。最後のセグメントは1.8秒伸ばし(素材が足りなければ最後のコマを止める)、映像と音を1.4秒でフェードアウトする
- concatで結合してからASSを焼き込む。セグメントを再利用するときは、セグメントの番号と構成がずれていないか確認する(構成を変えたら古いセグメントは消す)
- 最終エンコード:libx264で、1ファイル20MB以内に収まるビットレートにする(PCへの書き戻しの上限が20MB)。`-movflags +faststart`
- **縦横比・色のメタデータ**:書き出し済みのファイルを直すときは、`-c copy -bsf:v h264_metadata=sample_aspect_ratio=1/1:video_full_range_flag=0:colour_primaries=1:transfer_characteristics=1:matrix_coefficients=1 -aspect 1080:1920`
- 書き出したら、ffprobeで映像と音声の長さが一致しているか、数コマを並べたコンタクトシートで見た目がおかしくないかを確かめる

## 5. 音声
- 通常版:`alimiter=limit=0.46:attack=1:release=50:level=false` → 実測ピーク約-6.1dB
- YouTube用:`highpass=f=80, equalizer=f=250:g=-2, equalizer=f=3500:g=3, highshelf=f=8000:g=2, acompressor=threshold=-28dB:ratio=3:makeup=6dB, loudnorm=I=-15:TP=-6.5:LRA=7, alimiter=limit=0.5` → 声が聞き取りやすく、音量が安定する(ユーザーから「YouTubeで音がこもる問題がなくなった」と確認済み)。loudnormは末尾が欠けることがあるので、`-t` で長さを固定する
- ユーザーの効果音を入れるとき:鳴っている約1秒だけゲーム音を-5dB下げ、効果音は+8dB。立ち上がりのずれを補正して、映像の動きに合わせる
- 書き出したら、ebur128で真のピークを確かめる
- Premiere Proで編集して書き出し直すと、ピークが-5dBを超えることがある(参考作品では-4.6dB)。そのときは、Premiereの書き出し前にハードリミッター(-5.5dB)をかけるようユーザーに伝える
- YouTubeでだけ音がこもる場合は、視聴側の「安定した音量」、Shortsの編集画面での音楽追加、アップロード直後の処理中を疑う

## 6. 送り方
- チャットに送れるのは1ファイル30MBまで。超える場合は2800kbpsのプレビュー版を送り、元の画質のものはユーザーのフォルダに書き戻す
- PCとの接続が切れていたら、チャットに送ったうえで、接続が戻ったらフォルダに保存すると伝える

## 7. 投稿
- タイトルにハッシュタグ1〜2個、説明文に3〜5個(先頭の3つがタイトルの上に出る。60個を超えるとすべて無視される)
- 例:`#VTuber #Dimraeth #VTuber切り抜き #ゲーム実況 #shorts`。タグ欄には名前の表記ゆれ(ルミロール, lumi_roll, まりょゆぐどらく, マリョ など)を入れる
- タグの効果は小さい(YouTube公式)。タイトル・サムネイル・説明文を優先する
- クレジット表記が必要な素材(魔王魂など)を使ったら、説明文に入れるよう伝える

## 8. 後片付け
- 作業が終わったら、「ダウンロード」フォルダに残った素材(`lumi_…`、`whisper_…`、`se_…`、`.tmp`)と、古い版の書き出しファイルを列挙して、削除してよいとユーザーに伝える(削除はユーザー本人にしてもらう)
