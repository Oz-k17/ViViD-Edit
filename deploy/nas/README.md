# UGREEN NAS に置いて、何人かで使う

（UGOS Pro での手順です。Synology / QNAP / 自作でも、パスを読み替えれば同じ形で動きます。）

ViViD Edit は全部ブラウザの中で動くので、サーバは「ファイルを配るだけ」で足ります。
NAS に nginx を 1 つ立てて、**アプリと共有素材を同じ口から配る**のがここでの構成です。

これで得られるもの:

- 配布が URL 1 つになる（各自インストール不要、iPad でも PC でも同じ）
- 更新が NAS のファイル差し替えだけで済む（全員に配り直さなくていい）
- 素材をコピーせずに参照できる（各自のブラウザの保存枠を食わない）
- プロジェクトをファイル 1 個で渡せる（相手の環境でも同じ素材が開く）
- 外に出ない（インターネットに繋がっていなくても動く）

## なぜ「同じ口」なのか

ブラウザは、ページの出どころと違うホスト・違うポートへの読み込みを既定で止めます（CORS）。
アプリを `:8080`、素材を WebDAV の `:5005` に分けると、素材が読めません。
1 つの nginx から `/` と `/media/` として出せば、同じオリジンになるのでこの問題が起きません。

UGREEN NAS の WebDAV（既定 5005 / 5006）を使わないのはこのためです。
WebDAV は口が別なので、そちらに素材を置くと同じ問題にぶつかります。

## 置くもの

```
/volume1/docker/vivid-edit/
├── app/              ← このリポジトリの docs/ の中身をそのままコピー
│   ├── index.html
│   ├── assets/
│   └── lab/
└── nginx.conf        ← deploy/nas/nginx.conf をこの名前で
```

`docker-compose.yml` はここに置かなくて構いません。UGOS の画面に貼り付けるだけです。

**パスはすべて絶対で書いてください。** UGOS はプロジェクト用のフォルダを自分で決めるので、
`./nginx.conf` のような相対パスだと、こちらが置いた場所ではなくそのフォルダを見に行きます。
ここで一度つまずくと原因が分かりにくいので、compose 側も全部 `/volume1/...` にしてあります。

共有素材は別のフォルダにしてください。アプリの入れ替えで巻き込まないためです。
UGOS の共有フォルダは `/volume1/<共有フォルダ名>` になります（共有フォルダ名が `video` なら `/volume1/video`）。

```
/volume1/video/shared/
├── 2026-09-案件A/
│   ├── cut01.mp4
│   └── bgm.wav
└── ロゴ.png
```

## 手順

**前に確かめること**: Docker は UGOS Pro の App Center から入れます（DXP 系・DH4300 Plus で使えます）。

1. **ファイルを置く**
   ファイルマネージャで `docker` 共有フォルダに `vivid-edit/app/` を作り、
   このリポジトリの `docs/` の**中身**をコピーします（`docs` フォルダごとではなく中身）。
   `deploy/nas/nginx.conf` は `vivid-edit/nginx.conf` として置きます。

2. **素材フォルダのパスを確かめる**
   ファイルマネージャで共有フォルダを右クリック → プロパティで実際のパスが見られます。
   だいたい `/volume1/<共有フォルダ名>` です。

3. **compose の 3 行を書き換える**
   `deploy/nas/docker-compose.yml` の `volumes` の左側を、実際の場所に合わせます。

   ```yaml
   - /volume1/docker/vivid-edit/app:/srv/app:ro                              # ① アプリ
   - /volume1/docker/vivid-edit/nginx.conf:/etc/nginx/conf.d/default.conf:ro # ② 設定
   - /volume1/video/shared:/srv/media:ro                                     # ③ 共有素材
   ```

   素材側の `:ro`（読み取り専用）は外さないでください。編集アプリから素材を消せる必要はありません。

4. **Docker で立ち上げる**
   `Docker` → `プロジェクト` → `作成` を開き、compose の中身を貼って作成します。
   コマンドラインは要りません。

5. **開く**
   `http://<NAS の IP>:8080/` を全員に配ります。`8080` が他と当たるなら compose の左側だけ変えてください。

6. **素材を入れる**
   編集画面の素材パネル → **「共有」** を押すと、`/media/` の中身が一覧されます。
   選んで追加すると、**コピーせずに参照**として入ります。

## 更新のしかた

`app/` の中身を、新しい `docs/` の中身で差し替えるだけです。コンテナはそのままで構いません。
`index.html` にはキャッシュを持たせていないので、各自が再読み込みすれば新しい版になります。

## プロジェクトの受け渡し

`設定` → `プロジェクトの受け渡し` から、編集内容をファイル 1 個（`.vivid.json`）で書き出せます。
受け取った人は同じ画面の「プロジェクトを開く」で開けます。

素材は**在り処だけ**が入っているので、相手にも同じ共有フォルダが見えている必要があります。
取り込み（ファイル選択で入れた）素材はその端末の中にしか無いため運べません。
書き出すときに、運べない素材があればその名前を知らせます。

## 先に手元の PC で試す（NAS の権限が無くてもできます）

UGOS の**公式デモや仮想環境はありません**（ハードウェア前提で、体験版は提供されていません）。
ただ、UGOS の Docker は普通の Docker なので、**貼るものは同じ**です。
`docker-compose.local.yml` を使えば、自分の PC で一通り予行できます。

```
（空のフォルダを作って、その中で）
docker-compose.local.yml   ← このリポジトリから持ってくる
media/                     ← 皆で使う素材のつもり
media-personal/sato/       ← 人ごとのフォルダ

docker compose -f docker-compose.local.yml up -d
→ http://localhost:4193
片付け: docker compose -f docker-compose.local.yml down -v
```

NAS 版との違いは**マウント先の 2 行だけ**です。

**ここで確かめられること:** GitHub からアプリを取ってこられるか（NAS でも同じ処理です）、
共有 / 個人の素材が見えるか、プレビュー・書き出し・受け渡し、使う人の切り替え。

**ここでは確かめられないこと:**

- **UGREENlink のショートカットで外から開けるか** — 実機でしか試せません
- **http で配ったときの書き出しの落ち方** — `localhost` は例外的に安全なコンテキスト扱いなので、
  手元では通ってしまいます

## 外から使う

やり方は 2 つあります。**まず UGREENlink を試してください。**

### 1. UGREENlink（おすすめ・貼るだけ）

`docker-compose.ugreenlink.yml` を UGOS の「Docker → プロジェクト → 作成」に貼るだけです。
**NAS にファイルを上げる作業はありません**（アプリを GitHub から取ってきます）。

立ち上げたらデスクトップに**このコンテナのショートカットを作ってください**。
UGREENlink ID でログインしていれば、そのショートカットから外出先でも開けます。
ポート開放も固定 IP もドメインも要りません。

URL は https なので、下に書いた書き出しの問題も起きません。

> 以前この README には「UGREENlink はこの用途には使えない」と書いていましたが、**誤りでした。**
> UGOS Pro には、コンテナの Web 画面をショートカット経由で外から開く仕組みがあります。

**実機で最初に確かめてほしいこと:**

1. ショートカットが外の回線から開けるか
2. **プレビューのシークができるか** — 中継が Range リクエストを素通ししないと壊れます。ここがいちばん怪しい
3. 素材の読み込み速度

2 が駄目なら、下のトンネル版に切り替えてください。

### 2. Cloudflare Tunnel

`docker-compose.tunnel.yml` に、Cloudflare Tunnel を足した版を置いてあります。
NAS から**外向きに**繋ぎにいく方式なので、ポート開放も固定 IP も要らず、CGNAT でも通ります。

**ドメインが無くても試せます。** その版（お試しトンネル）は account も domain も要りませんが、
URL が起動のたびに変わり、認証も付きません。実運用するならドメインを 1 つ用意して
名前付きトンネルにし、Cloudflare Access でログインを必須にしてください（50 人まで無料）。

### どちらでも変わらないこと

外から使うときの本当の天井は、**NAS 側の上り速度**です。1080p で 20Mbps、4K なら 100Mbps 前後を
1 人あたり食います。中継の種類を変えても、ここは変わりません。

## 何人かで使う

### 使う人を分ける

設定画面の「使う人」で切り替えます。**設定・下書き・取り込んだ素材は人ごとに別々に保存**されるので、
一台の編集用 PC を回しても混ざりません。

別々の端末で使うぶんには、そもそも保存先がブラウザごとに分かれているので、何もしなくても混ざりません。
この機能が効くのは**同じブラウザを複数人で使うとき**です。

> **仕切りであって、鍵ではありません。** 同じブラウザを開けば誰にでも切り替えられ、中身も見えます。
> パスワードはかかりません。

### 素材を「共有」と「個人」に分ける

設定画面の「素材の置き場所」で 2 つ設定します。

| | 中身 | 既定のパス |
|---|---|---|
| 共有素材フォルダ | 皆で使う素材 | `media/` |
| 個人素材の親フォルダ | この下に人ごとのフォルダが並ぶ | `media-personal/` |

個人側は「使う人」に設定したフォルダ名で決まります。佐藤さんのフォルダ名を `sato` にすると、
その人は `media-personal/sato/` だけを見ます。

NAS 側はこう置きます:

```
/volume1/共有フォルダ名/
├── 素材/              ← 共有（compose の ① に書く）
│   └── 案件A/
└── 個人素材/          ← 個人の親（compose の ② に書く）
    ├── sato/
    └── suzuki/
```

編集画面の「NAS」ボタンから、共有 / 個人 を切り替えて選べます。

> **個人フォルダは他の人からも見えます。** このアプリには誰が見ているかを知る手段がないので、
> フォルダ名さえ分かれば誰の個人フォルダでも開けます。**誰がどれを使うかの仕分け**であって、
> アクセス制限ではありません。人に見られて困るものは置かないでください。
> 本当に隠す必要があるなら、nginx 側で Basic 認証をかける必要があります（未実装）。

## http と https の違い（書き出しに効きます）

`http://` で配ると、ブラウザがそのページを「安全なコンテキスト」とみなしません。
すると **WebCodecs が使えず、1 コマずつの書き出しができなくなります**。
実時間で録画する方式に落ちるので、

- 尺と同じだけ時間がかかる
- 端末が重いとコマを落とす
- ファイルが数倍に膨らむ（実測で 8 倍になった）

編集とプレビューは問題なく動くので、気づきにくいのが厄介です。
書き出しの画面に注意書きを出すようにしてありますが、**可能なら https で配ってください。**
トンネルを通せば証明書は自動で付くので、LAN の人もトンネルの URL で開くのが結局いちばん速くなります。

（`http://localhost` と `http://127.0.0.1` は例外的に安全扱いです。手元で試すと気づけません。）

## 知っておくこと

- **同時編集はできません。** プロジェクトと設定は各自のブラウザの中にあります。共有されるのは素材だけです。
  逆に言うと、何人が同時に開いても**お互いの作業を壊しません**（サーバには誰も書き込まないため）。
- **開ける人を絞る仕組みはありません。** LAN 内の誰でも、また UGREENlink を通せばその ID を持つ人が開けます。
  絞るなら nginx 側で Basic 認証をかけるか、NAS のファイアウォールで。
- **iPad の Safari は、長く使わないサイトのデータを消すことがあります。** 大事な編集途中のものは、こまめに書き出しておいてください。

## うまくいかないとき

**素材が 403 で読めない**
nginx のワーカーから素材フォルダが読めていません。共有フォルダの権限を確かめてください
（`everyone` に読み取りがあるか、少なくとも辿れるか）。

**一覧は出るのに再生できない**
素材フォルダのマウント（③）は合っているが、その中のファイルに読み取り権限が無い場合です。

**設定を変えたのに反映されない**
`nginx.conf` を書き換えたら、UGOS の Docker 画面でコンテナを再起動してください。

## 素材の一覧が出ないとき

アプリは 3 通りの方法で一覧を読みます。上から順に試し、最初に読めたものを使います。

1. nginx の `autoindex_format json`（この構成はこれ）
2. ふつうの HTML のフォルダ一覧（`autoindex on` だけの場合）
3. フォルダに置いた `media.json`

Web サーバに一覧を出させられない場合は、素材フォルダに `media.json` を置いてください。

```json
["cut01.mp4", "cut02.mp4", "bgm.wav", "素材置き場/"]
```

末尾が `/` のものはフォルダとして扱われます。
